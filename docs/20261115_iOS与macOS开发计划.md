# iOS / macOS 开发计划（黑苹果构建机）

> 2026-11-15 制定。前置研究见 `docs\20261115_iOS与macOS版本可行性研究.md`。
> 本文是排期与执行计划：以**黑苹果为唯一 Apple 构建机**，先跑通 Phase 0 冒烟再立项 Phase 1。

## 0. 黑苹果锁死的工具链（硬约束链，先看这个）

```
Intel 黑苹果 → macOS 最高 Sequoia 15.x（macOS 26 Tahoe 仅 Apple Silicon）
            → 只能装 Xcode 26.6（Xcode 27 要求 macOS 26.6+）
            → .NET 10 iOS/MacCatalyst workload 必须钉在「要求 Xcode 26.6」的那套
              （现有数据：workload set 10.0.401 = iOS 26.5.10318 ↔ Xcode 26.6；
               实装当天以 dotnet/macios release notes 与 aka.ms/xcode-requirement 复核）
            → iOS 26 SDK；无需 UIScene 生命周期迁移（那是 Xcode 27 的强制项）
```

**推论（都要接受）**：
1. SDK 停在 iOS 26 一代，落后当前 iOS 27 SDK 一个版本——内网录入工具无碍，但新 API 不可用；
2. .NET SDK 钉 `10.0.401` + workload `--version` 显式钉住（`dotnet workload update` 会自动跳到要 Xcode 27 的版本，**必须禁止裸更新**）；
3. Xcode 关闭自动更新，多版本并排装、用 `DEVELOPER_DIR` 切换；
4. 测试 iPhone 尽量停在 **iOS 26.x**（Xcode 26.6 向 iOS 27 设备部署需实测，见风险 R3）。

## 1. 第 0 周：黑苹果体检与决策门（3~5 天，跑不通就停）

| # | 任务 | 验收标准 |
|---|---|---|
| T0.1 | 黑苹果体检：macOS ≥15.6（Sequoia）、OpenCore 版本、**GPU 加速**（AMD/Intel 核显 OK；NVIDIA 独显无驱动 = 模拟器/Xcode 卡到不可用）、磁盘余量 ≥100GB（Xcode ~40GB + SDK） | `system_profiler` 确认显卡驱动生效；系统信息无"软件正在运行" |
| T0.2 | 装 Xcode **26.6**（并排命名 `Xcode_26.6.app`），`xcode-select` 指向它，license + 首次运行完成 | `xcodebuild -version` = 26.6；iOS 26 Simulator runtime 可启动 |
| T0.3 | 装 .NET SDK **10.0.401** + `dotnet workload install maui ios maccatalyst --version <匹配集>`（钉住） | `dotnet workload --info` 显示钉定集；`dotnet build -f net10.0-ios` 对样例工程零错误；Xcode 版本校验无 E0191 |
| T0.4 | Apple 账号：先用**免费 Apple ID**（真机签名 7 天有效）跑通；立项后补 $99 付费账号（Ad Hoc/长期签名） | 免费账号真机安装成功 |
| T0.5 | 仓库与分支：黑苹果 clone `xingjianya-86/NewCosmos`，基于合并 PR #8 后的 `main` 开新分支 `feat/ios-macos-platform` | 分支创建，Windows 侧继续在该分支协同 |
| T0.6 | iOS 最小骨架：`NewCosmos.csproj` 加 `net10.0-ios`（**所有既有条件项按 `TargetPlatformIdentifier` 逐条隔离**，不动 windows/android 分支）、`Platforms\iOS\`（Program/AppDelegate/Info.plist/Entitlements）、空壳页 | **三端编译各零错误**（Windows/Android 回归不受影响；iOS 在黑苹果上编） |
| T0.7 | 真机冒烟：登录页 + 直连 PostgreSQL（同 WiFi / 内网穿透）→ 登录 → 列表 | **决策门**：跑通 → 立项 Phase 1；任何一步卡死 → 记录 blocker、暂缓立项 |

## 2. Phase 1：数据录入端子集（4~6 周，与 Android 版同口径）

> 分支策略：`feat/ios-macos-platform` 上按周开子批次，每批 Windows/Android 双端回归零错误、Windows 上 `dotnet test` 全过后再合入。

| 周 | 任务 | 要点 |
|---|---|---|
| W1 | 平台服务 11 接口的 iOS 实现 + 密钥替换 | `IFilePicker/IFolderPicker`→UIDocumentPicker、`IAlbumExport`→Photos、`ISystemBars/INetworkAccess` 薄封装、`IAppPackageInstaller`→itms-services 占位；`ConfigService` 的 **DPAPI → Keychain**（`#if IOS` 分叉，Windows/Android 不动） |
| W2 | 数据链路与启动配置 | Npgsql 在 iOS 的 AOT/裁剪设置（首版关 Trimming 换稳定）；`database.ini` 凭据走 Keychain；登录会话/心跳/区域字典冒烟；**禁用开关**：启动动画→`LoginStyle=classic`、彩票预测入口隐藏、Word/COM 直出隐藏 |
| W3 | 业务表单全量 | 低收入/高龄/临时救助 列表+表单+导入（EPPlus/NPOI + 文件选择）+ 档案查询/产出只读；权限与数据范围 |
| W4 | 照片链路（核心价值，代码基本零改动） | MediaPicker 拍照/相册 → `SavePhotoAsync` 水印（SkiaSharp 复用）→ 上传；补传页+会话；档案照片查询页；OCR 远程识别（HTTP 客户端复用）；扫描页首版 MediaPicker 兜底（无实时取景框）；相册导出 |
| W5 | 打印与输出 | 照片/文书**推送入队**（PC 打印代理执行，iOS 不做本地打印）；文书导出保留"推送到 PC"；手机工作台入口适配 |
| W6 | 回归与上真机全链路 | Android 版对照表逐项打勾（≥15 条核心冒烟路径：登录→三表单保存→导入→拍照水印→补传→OCR 回填→打印推送→导出）；启动耗时/包体积/耗电粗测；Info.plist 权限文案（相机/相册/定位/本地网络） |

**Phase 1 验收**：一台 iPhone 上完成"进村采集一天"的真实演练（离线断连恢复、拍照 100 张、批量上传）。

## 3. Phase 2：体验补齐与 macOS 版（2~4 周）

| # | 任务 | 说明 |
|---|---|---|
| P2.1 | 启动动画/序列登录 | `AnimationWebViewView` 补第三套 WKWebView 虚拟主机+JS 桥实现（WebView2 已全部圈在 `#if WINDOWS`，非 Windows 路径有现成结构可参照 Android）；做不完则长期走经典登录（已有无感回退） |
| P2.2 | OCR 实时取景 | `CameraPreviewViewHandler` 的 AVCaptureSession 版（Android 有完整参照） |
| P2.3 | PDF 预览实测 | `PdfPreviewView` 已是 MAUI WebView + PDF.js + base64 注入，iOS 基本可用，实测 WKWebView 本地资源与内存 |
| P2.4 | **Mac Catalyst 版** | 加 `net10.0-maccatalyst`（同一套 iOS 代码上 macOS 15；黑苹果可直接跑）；桌面布局复用现有 `DeviceIdiom` 响应式分叉；文件选择/系统栏按 Catalyst 适配 |
| P2.5 | 打包脚本 | 黑苹果侧新增 `deploy/publish_ios.sh`：`dotnet publish -f net10.0-ios -c Release` → codesign → IPA → 内部 OTA 清单（itms-services）；与 Windows 的 `publish_all` 并列，互不阻塞 |

## 4. 分发（与 Phase 1 并行推进）

1. **开发调试**：黑苹果 Xcode 直连真机（免费账号 7 天 / 付费账号 1 年）；
2. **内部安装**：付费账号注册 ≤100 台设备的 Ad Hoc 描述文件 → IPA + **itms-services OTA 页**（复用现有内网 HTTP 服务器，仿 `update.json` 清单风格新增 `ios/install.plist`）——被 iOS 禁止的"App 内自更新"由此绕开；
3. 上架 App Store / 企业证书：**暂缓决策**（民政敏感数据合规风险，见可行性研究 §4）。

## 5. 风险表（黑苹果专属已标注 ⚠）

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | ⚠ 黑苹果封顶 Sequoia → Xcode 封顶 26.6 → SDK 封顶 iOS 26 | 高（已接受为前提） | 钉死工具链；新 API 需求走"PC 端实现"；长期若必须 iOS 27+ SDK，改用云 Mac（macrun.dev 等按需租用）或真 Mac |
| R2 | ⚠ workload 裸更新跳到要 Xcode 27 的版本 → 构建全断 | 高 | `--version` 钉集 + 禁 `dotnet workload update`；升级只允许"改钉值 + 双端回归"一次完成 |
| R3 | 测试机 iOS 27 与 Xcode 26.6 部署兼容性 | 中 | T0.7 实测 `xcrun devicectl list devices` → 部署链路；失败则测试机系统停留在 26.x 或借一台旧系统设备 |

| R5 | GPU 无加速 → 模拟器/Xcode 极卡 | 中 | T0.1 体检；真机调试为主，模拟器仅作辅助 |
| R6 | Xcode 自动更新跳版破坏匹配 | 中 | App Store 关闭 Xcode 自动更新；多版本并排 + `DEVELOPER_DIR` |
| R7 | Npgsql 全 AOT 行为差异 | 中 | Phase 1 首版关 Trimming；W2/W6 重点回归查询映射（380+ 列宽表） |
| R8 | 三端条件项互相污染（csproj/`#if` 改坏 Windows/Android） | 中 | 每批强制 Windows+Android 双端零错误构建 + `dotnet test` + `check_standards` |
| R9 | 免费账号 7 天签名过期打断调试 | 低 | 立项即购 $99 付费账号 |

## 6. 里程碑

| 里程碑 | 内容 | 预估 |
|---|---|---|
| **M0 决策门** | T0.1~T0.7：黑苹果跑通 iOS 真机"登录→查库" | 3~5 天 |
| **M1 录入端内测** | Phase 1 六周任务全部验收，Ad Hoc + OTA 可装 | +4~6 周 |
| **M2 体验+macOS** | Phase 2（动画/取景/Catalyst/打包脚本） | +2~4 周 |
| M3 分发常态化 | `publish_ios` 融入发版节奏、文档与 CHANGELOG 规范同步 | 持续 |

**总量**：M0+M1 ≈ **1.5~2 个月**到 iOS 内测版；macOS（Catalyst）版随 M2 交付。

## 7. 与现有发版纪律的衔接（AGENTS §2）

- iOS 包不进 Windows 的 `publish_all.bat`（Inno/APK 流水线），由黑苹果 `publish_ios.sh` 独立出包；
- 版本号仍三处同步口径（csproj 版本由 iOS 侧共读），**CHANGELOG 照旧唯一素材来源**——随包内置日志（`EmbeddedResource`）在 iOS 包同样生效；
- 每个里程碑完成照写 `CHANGELOG.md` 未发布段；黑苹果侧不存任何凭据明文（签名证书口令走 Keychain，OTA 清单无私钥）。
