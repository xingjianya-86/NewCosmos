# 手机端界面重构方案

> 更新日期：2026-09-20。将手机端与 PC 端界面风格彻底拆分，后台代码复用一套。

## 背景

- 当前 `MainPage.xaml` 是 1920×1080 固定桌面布局，手机端完全不可用
- Android 定位为**数据录入版**（`docs\20260920_Android数据录入版部署教程.md`），但缺少手机专用界面
- Office COM 打印提示在 Android 上不必要且导致启动失败
- 用户需求：重新设计手机端 UI、推送打印、身份证 OCR 读取

## 技术决策

| 决策项 | 选择 |
|---|---|
| UI 拆分架构 | 独立手机页面目录 + IPageResolver 自动解析 |
| 身份证读取 | PaddleOCR 离线内置（摄像头 OCR，设备端处理） |
| 推送打印 | 数据库队列 + PC 端打印代理（嵌入 Windows 客户端） |
| 手机端首期范围 | 家庭经济状况核对模块 |

## 架构

### UI 分离

```
Pages/
  Mobile/                          ← 手机专用页面
    MobileMainPage.xaml            （底部 Tab 手机壳）
    AssetVerification/
      MobileAssetVerificationHomePage.xaml
      MobileQuickVerificationPage.xaml
      MobileMonthlyAuditPage.xaml
ViewModels/Mobile/
  MobileMainViewModel.cs           （仅手机壳 VM）
Services/Platform/
  IIdentityReader.cs               （身份 OCR 读取抽象）
  IPrintQueueService.cs            （推送打印队列抽象）
Components/
  IdentityInputView.xaml           （可复用：姓名+身份证+拍照读取）
```

### 页面解析

`IPageResolver`：`NavigateToPageAsync<TPage>()` 在 Android 上自动查找 `Mobile{TPage}` 页面，找不到回退 PC 页。业务 ViewModel 零改动。

### 推送打印数据流

```
手机（推送打印）→ PostgreSQL（nc_biz_print_jobs 表）→ PC 代理轮询 → Office COM 打印
```

### OCR 流程

```
拍照 → PaddleOCR 离线识别 → 字段提取 → IdCardValidator 校验 → 自动填入
```

## 实施步骤

### Phase 0 — 备份与准备
- 备份将改动的文件到 `backup\<时间戳>_mobile_ui\`

### Phase 1 — 屏蔽 Office（Android）
- `MainViewModel.cs:386-400` Office 检查加 `#if WINDOWS`
- `OfficeProviderDetector.cs` 加守卫
- 打印/导出命令 Android 隐藏

### Phase 2 — 手机/PC UI 分离
- `IPageResolver` + `ConventionPageResolver`
- `MobileMainPage` 手机壳
- 登录成功后按平台选择主页面
- DI 注册

### Phase 3 — 家庭经济状况核对手机页面
- 手机核对首页（卡片式）
- 快速核对手机版
- 月度审核手机版

### Phase 4 — 推送打印
- 新建 `nc_biz_print_jobs` 表
- `IPrintQueueService` + `PrintQueueService`
- PC 打印代理（Windows 客户端轮询）

### Phase 5 — 身份证 OCR
- `IIdentityReader` 抽象
- PaddleOCR + ONNX Runtime 集成
- `IdentityInputView` 可复用控件
- 替换核对模块 3 处身份输入

### Phase 6 — 联调与收尾
- 双平台编译 + 冒烟
- 文档更新

## 验证

1. Windows 编译零错误 + 冒烟
2. Android 编译 + 真机安装
3. 端到端：登录→核对→OCR录入→推送→PC打印
4. 文档更新

## 风险

| 风险 | 应对 |
|---|---|
| PaddleOCR 集成最重 | 先做抽象与拍照，OCR 引擎单独里程碑 |
| PC 代理依赖客户端常驻 | 先嵌入客户端，后续可拆独立程序 |
| 导航改动影响全局 | 保持回退逻辑，Windows 行为不变 |
