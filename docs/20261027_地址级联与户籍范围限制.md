# 地级联全国化与户籍管辖范围限制

> 更新：2026-10-27（首版）。适用：低收入人口认定表单、普惠高龄表单（PC + 手机端）。
> 单一事实来源：可执行逻辑以源文件为准；本文只保留规则、口径与挂点索引。

---

## 1. 需求与决策

| # | 决策 |
|---|---|
| 1 | **家庭住址（居住地）扩充为全国**：省由「写死单选 + 禁用」改为**全国 34 省可选**；居住地**不做**任何范围限制 |
| 2 | **户籍地址限制为当前登录用户所在单位的管辖范围**，逐级限制 |
| 3 | 限制方式：**账号绑定的那一级及以上 → Picker 置灰禁点 + 选项只留本单位一项**（=「其他全部禁用」）；**以下级**才开放选择（仍过滤在管辖范围内） |
| 4 | **未绑定区划的账号 → 整个地址区禁用**（严格阻断，不降级），并给红条指引 |
| 5 | **只限户主两组**（户籍 + 家庭住址）；表单内家庭成员的地址**不受限制** |
| 6 | **全国市/县/镇/村数据后补**：机制先做，选了无数据的省 → 市列表为空 + 明示提示；数据导入后零代码生效 |

## 2. 管辖范围（单点口径）

`Services/Core/IAddressScopeService.cs` / `AddressScopeService.cs`（Singleton，**进程内缓存一次**）：

```csharp
AddressScope.LockLevel   // 0=未绑区划  1=省  2=市  3=县  4=镇  5=村
                         // 自村向上取第一个已绑定层级（AddressScope.ComputeLockLevel）
IsProvinceLocked => LockLevel >= 1    IsCityLocked => LockLevel >= 2
IsCountyLocked   => LockLevel >= 3    IsTownLocked => LockLevel >= 4
IsVillageLocked  => LockLevel >= 5
```

来源：`App.CurrentUserOrganizationId → IOrganizationService.GetByIdAsync → org.province_id/city_id/county_id/town_id/village_id`。

### 逐级限制表（= 户籍可选范围）

| 账号绑到 | 省 | 市 | 县 | 镇 | 村 |
|---|---|---|---|---|---|
| 村 | 锁 | 锁 | 锁 | 锁 | **锁=本村（默认选中，其余项被过滤掉）** |
| 镇 | 锁 | 锁 | 锁 | 锁 | 开放：本镇下辖村 |
| 县 | 锁 | 锁 | 锁 | 开放：本县各镇 | 开放：所选镇的村 |
| 市 | 锁 | 锁 | 开放 | 开放 | 开放 |
| 省 | 锁 | 开放（全省） | 开放 | 开放 | 开放 |
| **未绑区划** | **整个地址区禁用** + 红条「请先到经办机构管理补齐区划」 | | | | |

> MAUI `Picker` **没有单项禁用能力**，因此「其他全部禁用」的实现 = **锁定级 Options 只装本单位一项 + Picker `IsEnabled=False`**（置灰不可点）。

## 3. 两张表单的落地

### 3.1 低收入人口认定（`ApplicationFormViewModel*` + `ApplicationFormStep1View.xaml`）

| 组 | 现状 → 改后 |
|---|---|
| 户籍所在地 | 市/县/镇/村 4 级 → **受范围限制**：`AllowHukouCity/County/Town/Village` 过滤 Options；锁定级 `IsEnabled="{Binding IsHukouXxxLocked, Converter=BoolToInverse}"`；`HukouProvince` 由写死常量 `HOME_PROVINCE` 改为**取 `AddressScope.ProvinceName`** |
| 家庭住址 | 省 = `ProvinceOptions` 只放一个写死值且 Picker `IsEnabled="False"` → **改为 34 省可选**（`GetProvincesAsync()`），去掉禁用；选省 → `GetCitiesByProvinceIdAsync`；**不限范围** |
| 未绑区划 | 两张卡片 `IsEnabled="{Binding IsAddressScopeAvailable}"` + 顶部红条 |

- `ProvinceOptions` 默认选中：账号所在省 → 常量兜底
- 省表缺失（迁移未跑）→ 省选择器回退单值占位，**不阻断表单**

### 3.2 普惠高龄（`ElderlyApplicationFormViewModel*` + `ElderlyApplicationFormPage.xaml` + `MobileElderlyApplicationFormPage.xaml`）

- 户籍/家庭住址两组从 4 级 → **5 级（补省 Picker）**；县 ID 列 `hukou_county_id/family_county_id` **库里本来就有**，只是 PC 端 XAML 没显示县 Picker（已补）
- 户籍组同样 `AllowHukou*` 过滤 + 锁定置灰；家庭住址组全国可选不限
- 省**不落库**：省由市隐含（`city_code` 前 2 位），省 Picker 只作级联入口 → **零 DB 改动**
- 两处入口（`LoadInitialRegionAsync` 新建 / `LoadRegionCascadesForEditAsync` 编辑）各调 `EnsureAddressScopeAsync()`（解析范围 + 装省列表）

## 4. 全国数据后补

| 级 | 现状（黑龙江） | 全国 |
|---|---|---|
| 省 | **34 省（全国）✓ 已就位** | — |
| 市 | 13 | ~333 |
| 县 | 125 | ~2,800 |
| 镇 | 1,703 | ~41,000 |
| 村 | 14,451 | ~600,000 |

- 机制已就绪：`RegionService.GetProvincesAsync()` / `GetCitiesByProvinceIdAsync(int)`（**旧 `GetCitiesAsync()` 签名不变 → 8 个既有消费方零改动**）
- 选了**无数据的省** → 市/县/镇/村级联全空 + 日志 `Warn`（家庭住址侧还会清空已选项，避免残留错值）
- 数据到位后只需按省导入 `nc_regions_cities/counties/towns/villages`（**导入脚本待全国区划数据文件到位后编写**）
- ⚠️ 村是**按镇缓存**（`_villagesByTownCache`），无全量村缓存 → 60 万村**不会**吃内存

## 6. 冒烟清单

1. `dotnet build` **0 错 0 警**。
2. **镇级账号**（如 柳树镇民政办）进认定表单：户籍 省/市/县/镇 **四个 Picker 置灰**且已选中本单位值，**村下拉只有本镇村**；家庭住址**省可下拉选 34 省**，选外省 → 市空并有日志提示。
3. **村级账号**：户籍五级全锁，村只有本村一项。
4. **县级账号**：省/市/县 锁定，镇/村可选本县内。
5. 高龄表单（PC + 手机）：两组均 5 级；户籍组同样限制；家庭住址组不限。
6. **未绑区划账号**：两张表单**整个地址区禁用** + 红条指引（组织 Id=1 林口县民政局即此情形）。
7. **成员行地址不受限制**（决策 5）。
8. 组织管理页 / 区划管理页 **不受限制**（管理页要看全部）。

## 7. 边界与未含

1. **全国市/县/镇/村数据不在本批**（见 §4），导入脚本待数据文件
2. **高龄表省不落库**（省由市隐含；省 Picker 只作级联入口）
3. 配偶信息/临时救助 **无地址级联**，不涉及
4. 成员行地址不加限制
5. 手机端低收入认定表单（`MobileApplicationFormPage`）**本就无地址级联**，无需改动
