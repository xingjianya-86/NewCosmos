## 三、数据口径与边界

1. **死亡表**：`GetDeathRowsAsync` 已按 `nc_biz_applications.classification_result = ANY($4)` 过滤；分类名为空时不过滤，即「全部」。
2. **退出表**：`GetExitRectificationRowsAsync` 新增 `category` 参数；按事件「退出前分类」过滤（事件 `old_classification` 优先，空时回退档案当前分类），**先过滤、后同人去重**，避免同一人跨类别多条事件时被去重吞掉而漏人。
3. **未归类的行/事件只进「全部」**：
   - 死亡表：只申报、未关联档案的死亡行分类为空；
   - 退出表：退出前分类为「收入超标/不符合认定条件」等停止码或为空的行。
4. **去重口径差异**：
   - 死亡表无去重：四类分表行数之和 + 未归类行数 = 「全部」行数；
   - 退出表「全部」按身份证全局去重（一人一行，取最终退出事件）；四类分表是**先按分类筛选、再在分类内去重**，同一人跨类别有多条退出事件时会分别出现在对应分类表中。因此退出表四类之和**不一定**等于「全部」行数；「全部」仍是一人一行的最终退出视图。这样处理是为了避免先去重把低优先级类别的事件吞掉、导致该分类分表漏人；同一人跨类别时，分类表展示该类别的事件，「全部」展示最终退出事件，行的停止月份/原因可能不同。
5. 「全部」与四类分表同时勾选/全部保存时会产生重复口径的文件，属预期行为。
