# 户主死亡/变更新建新档：本人字段与"免于劳动力判定"残留修复

> 日期：2026-11-19 ｜ 触发：张桂秋（档案115，户主死亡停旧建新产物）
> 现象：新档表单保存报「家庭成员[张桂秋]勾选了"因照顾重病重残亲属免于劳动力判定"，但本户未勾选任何重病或重残成员」；
> 主表还带着死者倪德奎的"恶性肿瘤/胃恶性肿瘤/SevereIllness"。
> 关联：`docs/20261119_告知书停止与不予认定方向判定.md`（同日另一缺陷，互不影响）。

---

## 1. 数据事实（旧档56 → 新档115）

| 档案 | 事实 |
|---|---|
| 56（户主倪德奎，Stopped） | 主表 `is_severe_disease=t`、成员992 倪德奎 `is_severe_disease=t`（照顾目标）；成员619 张桂秋 `is_labor_exempt=t`（照顾重病丈夫） |
| 115（新户主张桂秋，Draft，死亡新建） | 成员1006 张桂秋 **`is_labor_exempt=t`**（整行复制残留）；主表 **`disease_name=恶性肿瘤 / secondary=胃恶性肿瘤 / health_status=SevereIllness`**（旧户主整行复制），且 `is_severe_disease=f`（不在主表 INSERT 列清单→默认 false）→ "健康=重病、重病勾选=否"自相矛盾 |

死亡原户主（倪德奎）被成员复制剔除（`id != $4`），照顾目标随之消失 → 豁免悬空 → 表单联动校验拦截保存。

## 2. 根因（`Services\Domain\ChangeManagement\ChangeService.DeathAndQueries.cs`）

1. **成员复制**（第9步，L566-593）：整行复制、只改新户主标记（`is_applicant`/`relationship_to_head`），
   `is_labor_exempt`/`is_severe_disease` 原样带过；死亡原户主被剔除后无人重算豁免是否仍成立。
2. **主表复制**（第8步，L509-514）：`physical_condition/disease_name/secondary_disease_name/
   disability_type/disability_level/health_status/disability_card_no/employment_status/work_unit/income_source`
   从**旧户主**整行复制，仅替换姓名/证件/电话/性别/民族/婚姻/户口性质/学历/政治面貌；
   `is_severe_disease` 不在列清单落默认 false。
3. **户主变更（非死亡）流程同型**（`ExecuteHouseholdHeadChangeAsync`）：StopAndRebuild 复制主表后只更新
   姓名/证件/性别/民族/婚姻五项，健康/残疾/就业等仍为旧户主数据。
4. **全代码库无任何 `is_labor_exempt = FALSE` 清理逻辑**（grep 证实），仅靠表单保存校验兜底；
   成员变更（减员剔除唯一照顾目标）同样会产生悬空豁免。

## 3. 修复

新增 `Services\Domain\ChangeManagement\ChangeService.MemberIntegrity.cs`（两个幂等助手）：

| 助手 | 口径 |
|---|---|
| `ClearInvalidLaborExemptAsync(applicationId)` | 与表单保存联动校验**同口径**：照顾目标 = 本户非豁免成员重病/重残（`is_severe_disease`/`is_severe_disability`）或户主本人主表重病/一、二级残疾（`DisabilityConstants.LEVEL1/2`）；目标不存在 → 清除 `is_labor_exempt`。无残留时 0 行更新，清除条数记 Info |
| `SyncHeadPersonFieldsAsync(applicationId, headMemberId)` | 主表"户主本人"字段从**新户主成员行**镜像：电话/性别/民族/婚姻/户口性质/学历/政治面貌/健康/疾病（名称+编码）/残疾类型等级/重病标记/就业/单位/收入来源；`physical_condition`、`disability_card_no` 无成员来源 → **清空**（旧户主证件号不得沿用） |

调用点（均在同一事务内，失败回滚）：

| 流程 | 调用 |
|---|---|
| 户主死亡停旧建新（`DeathAndQueries` 第9.5步） | 成员复制+映射后：`SyncHeadPersonFieldsAsync` + `ClearInvalidLaborExemptAsync` |
| 户主变更（`DeathAndQueries` 第4.5步） | 新旧户主关系更新后：同步 + 清理 |
| 停旧建新通用（`RebuildAndReview.StopAndRebuildAsync`，经济复核/成员变更） | 成员复制后：`ClearInvalidLaborExemptAsync`（成员未变时空操作；减员剔除照顾目标时生效） |

另：表单保存校验文案补齐"含户主本人"口径（`ApplicationFormViewModel.ValidationAndSubmit.cs`）。

## 6. 遗留 / 说明

1. `physical_condition`（身体状况）成员表无对应列，换户主后置空由经办人在新档表单重录（不沿用旧户主）。
2. 存量"主表与成员行字段格式差异"（如主表 `disease_name='无任何疾病'`、成员表用 `disease_category`）为历史导入格式，非本次缺陷，未动。
3. 减员流程本身若在**旧档**上先移除成员再停旧建新，旧档瞬间的悬空豁免由表单保存校验兜底；新档侧已由 `StopAndRebuildAsync` 收口。
