# 启动动画五幕拆分与序列登录（2026-11-15）

> 把 `Resources\Splash` 的单体动画拆成「core 引擎 + 五幕场景」，并以其中的
> **五步验证序列作为登录流程**（`app.ini LoginStyle=sequence`，默认开）：
> 启动动画 → 揭幕 → 序列登录（授权 → 账号密码 → 真实认证 → 核验通过 → 终幕进主页）。
> 本文只写拆分与序列登录；原移植说明见 `docs\20261027_启动画面移植与素材融合.md`。

## 1. 已定决策

| 决策 | 取值 |
|---|---|
| 登录形态 | **整页 WebView 序列登录**：LoginPage 加覆盖层承载 `login.html`，五步序列即登录流程 |
| 拆分粒度 | **完整五幕场景化**：core 引擎 + 5 个独立 scene，启动动画与登录共用 |
| 上线策略 | **默认 sequence，自动回落**：WebView 初始化失败 / 脚本回执超时 / 脚本异常 / 用户点「切换经典登录」→ 隐藏覆盖层即回落经典原生页（XAML 本就在底下渲染，无闪切） |

关键设计：**不新建页面类型**。`LoginPage` 类型不变，序列模式只是显示覆盖层——
`NavigationService.PageRegistry[Login]`、`App.SwitchToLoginPage`、Android `PageResolver` 回退全部零改动；
回落不需要换页、不重注册标题。

## 2. 拆分结构（core 引擎 + 五幕场景）

```
Resources\Splash\
├── splash.html          # 入口1：全时间线（行为与拆分前逐拍一致）
├── login.html           # 入口2：序列登录（只进 plate / verify / finale 三幕）
├── login.css            # 序列登录专属样式（表单行 / 错误行 / 失败红字，增量覆盖）
├── login.js             # 序列登录编排器（认证状态机 + 桥接 + 失败重试环）
├── core\
│   ├── anim-config.js     # DEFAULTS / cfg() / 共享状态 A.state（A.C 首次求值）
│   ├── anim-dom.js        # DOM 模板与引用表 A.buildDom、工具 el/typeIn/logoMark、时钟
│   ├── anim-audio-assets.js  # ★ 生成文件：mp3 → base64 data URI（见 §4）
│   ├── anim-audio.js      # WebAudio 音效引擎（优先读嵌入包，缺失回落 audio/*.mp3）
│   ├── anim-voice.js      # 台词引擎（素材优先 + TTS 兜底）+ A.wireSound 接线
│   ├── anim-chrome.js     # Windows 标题栏 overlay 透明同步
│   ├── anim-timeline.js   # 时间线引擎 wait/waitAction/进度/阶段柱/字幕/hex/准星
│   └── anim-runtime.js    # 统一收尾 A.finish（揭幕/跳过/异常同一出口）
├── scenes\
│   ├── scene-brand.js     # 第一幕：黑幕品牌 + 扫光
│   ├── scene-wash.js      # 过场：过曝洗白
│   ├── scene-plate.js     # 第二幕：档案底板（登录 skipFadeIn 直接进）
│   ├── scene-verify.js    # ★ 五步验证序列（STEPS + stepLoop + hooks 扩展点）
│   └── scene-finale.js    # 终幕：WELCOME + 色散故障揭幕
├── splash.js              # 编排器（原1490行 → 时序编排 + 对外 API）
├── bridge.js              # 双路上报保留；新增 __NC_BRIDGE__ 双向通道
├── splash.css / app.css   # 两入口共用同一份（底板一致铁律，不拆）
└── audio\*.mp3            # 素材源文件（嵌入包的生成来源；许可见 THIRD-PARTY-NOTICES.md）
```

- **加载顺序**（两入口相同）：`config.js → bridge.js → core/* → scenes/* → 编排器`，零依赖纯脚本。
- **对外契约不变**：`window.__DSH_STARTUP_API__`（含 audioDiag/replay/skip/finish）、
  `dsh-startup:done` 事件、`newcosmos-splash://` 协议、9 秒自举兜底、SKIP/Esc、`SplashGate` 40s 看门狗。
- **`stepLoop(rt, from)` + hooks**：`showAction / waitAction / afterStep(index)→'continue'|'abort'`
  是序列登录注入表单与认证关卡的扩展点；不传 hooks = 启动动画原行为。
- Windows 资产戳记（`SplashAssetsService`）已改为**全目录 SHA256 聚合**（拆分后只看 splash.js mtime 会漏子目录）。

## 3. 序列登录运行链路

```
login.html（ctx=login：强制 requireInteraction、黑幕隐藏、底板常显、SKIP 改「切换经典登录 ▸」）
  步骤1 系统访问许可 → 点「授予访问权限」/回车
  步骤2 操作员身份确认 → 身份卡片位换账号密码表单（记住账号密码经 prefill 预填）
        提交 → __NC_BRIDGE__.send('login-submit', {id,user,pass,remember,rememberPass})
  LoginPage.OnSequenceBridge → 写 LoginViewModel 属性 → LoginCommand（真实认证+建会话）
        → __NC_BRIDGE__.dispatch('auth-result', {id, ok, msg})   （id 去重，双路桥接各到一次）
  步骤3 接收请求 / 步骤4 读取权限（hex 流 = 认证在途的戏剧化；afterStep 关卡等结果）
        失败 → ABORT → 状态行红字「身份核验未通过」+ 表单错误行带服务端原因 → 从步骤2 重入
  步骤5 核验通过 → 终幕 WELCOME（line-6 欢迎语）→ dsh-startup:done
        → LoginPage.NavigateAfterAuthAsync → SetRoot(Main)（VM.DeferNavigation 延迟导航）
```

**宿主侧回落/兜底（任一触发即隐藏覆盖层，经典页无感接手）**：

| 条件 | 处理 |
|---|---|
| WebView2 初始化失败 / StartUrl 缺失 / 加载异常（`HostFaulted`） | 回落；若认证已成功则直接进主页 |
| 12s 无 boot 回执（`SplashConstants.WebBootTimeoutSeconds`，仅 Windows 有 postMessage 通道） | 回落 |
| 桥 `error`（window.onerror / unhandledrejection） | 回落（已认证成功则进主页） |
| 桥 `login-skip`（点「切换经典登录 ▸」/ Esc；认证前语义） | 回落（`DeferNavigation` 复位 false，关键） |
| 认证成功后 30s 无 done（`LoginDoneTimeoutSeconds` 终幕看门狗） | 不等动画，直接进主页 |
| login.js 自举 9s 兜底 / run() 链异常 | 上报 `login-fallback` → 回落 |

**SKIP 语义**：认证成功前 = 切经典登录页（`finish({silent})`，不派发 done）；
认证成功后 = 跳过剩余动画直接 `finish()` → done → 进主页。

## 4. 音频嵌入（mp3 零请求）

- 问题：启动 + 登录各是一套 WebView，启动时会对 `audio/*.mp3` 各拉一遍（本地流量也会刷满测试/监控日志）。
- 方案：`powershell -File Scripts\prepare_splash_audio.ps1` 把 `audio\*.mp3` 转 base64 生成
  `core\anim-audio-assets.js`（8 个文件 / 173KB → 232KB 资产包），两入口 `<script>` 引入；
  `anim-audio.js` 的 `assetUrl(name)` **优先读嵌入包**，清单缺失才回落 `audio/*.mp3`（旧模式）。
- 效果：任何环境（WebView2 虚拟主机 / APK assets / 本地 file:// 测试）**不再有一条 mp3 请求**；
  测试可直接用 `file://` 打开页面，不再需要本地 HTTP 服务器（上游当年起服务器只为绕开 file:// 下 fetch 受限）。
- 素材本体未改，`THIRD-PARTY-NOTICES.md` 与 `SplashSound=0` 静音策略继续适用；
  彻底移除音频时删 `audio\` 与生成的资产包即可，脚本自动退回 WebAudio 合成音。

## 5. 配置与安全

```ini
[Login]
LoginStyle=sequence   ; sequence=验证序列登录（默认）| classic=经典原生登录页
; 音效沿用 [Splash] SplashSound，速度沿用 SplashSpeed
```

- `AppOptions.LoginStyle / IsSequenceLogin` ← `ConfigService`（非法值回退 sequence 并告警，§11）。
- 凭据流向仅三处：web 表单 DOM → 桥消息（进程内，`Navigating` 立即 cancel / Android 拦截，
  **绝不入日志**）→ `LoginViewModel` 属性；不进 `config.js`、不进 Serilog（登录日志仍只记 UserId/UserName）；
  页面只引用本地资产，无外网请求；WebView 沿用禁 devtools/右键。

## 6. 冒烟清单

1. 默认 sequence：冷启动 → 动画 → 序列登录（音效随 `SplashSound`）→ 正常登录进主页；
2. 错误密码 → 红字失败态带原因 → 改对重试成功；
3. 记住账号/密码 → 表单预填；勾选随提交回存；
4. `LoginStyle=classic` → 与改动前完全一致的原生登录页；
5. 回落：改坏 login.html 或清空 AppData\Splash 后启动 → 12s 内无感出经典登录页；
6. 会话踢回登录（`NavigationKeys.Login`）同样走序列；启动动画 SKIP/Esc、`SplashEnabled=0` 行为不变；
7. Android 真机：IME 输入、键盘遮挡、声音、回落、断网诊断弹窗；
8. 无头冒烟（开发用）：`file:///` 直开 `splash.html` / `login.html`，看 console 无异常、
   登录场景 `DONE event` 抵达（参考本目录 `login_test.html` 的测试宿主思路，不入库）。
