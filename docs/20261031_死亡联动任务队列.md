# 死亡联动任务队列（方案2）规范

> 2026-10-31。单一事实来源：本文 + 指向的权威代码；易变清单给核对命令。
> 关联：`docs/20261026_死亡情况说明与申报台账规范.md`（§3.5 跨流程联动）、AGENTS §5/§8/§13。

## 1. 背景与决策

**问题**：死亡申报由村里提交（入口零门控，符合业务），但低保减员/户主死亡变更/高龄停发/大学生退出/追缴结案是**镇级手续**——村级无对应权限，联动卡"去办理"跳过去撞权限墙或绕过权限直接办（修复前三目标页零权限校验，村级可办镇级手续）。

**三项决策**（用户2026-10-31拍板）：
1. **任务队列承接（方案2）**：申报自动生成各域待办行，有权限的人在自己域的承接面办理（弃"仅权限分流导航"的轻量方案）；
2. **高龄承接面 = 待办列表新增 Tab**；
3. **大学生立权限码** `COLLEGE_MANAGE`；**手机端同步实现**。

**申报入口不加权限码**（任何 APP_ACCESS 账号可进可提交）——"谁先知道谁报"，权限只管"办手续"。

## 2. 核心口径（铁律）

| 铁律 | 说明 |
|---|---|
| **派活表 ≠ 办结回写表** | `nc_biz_death_linkage_tasks` 只记"哪个申报需要办哪些事"；**办没办成永远以目标域实时状态判定**（`DeathStatementService.GetLinkageTasksAsync` 的 CASE live 条件）。`status=Completed` 仅为读取时自愈标记，非事实源——目标域逻辑再变，任务状态不撒谎。§3.5「不新增办结回写表」原则**未破**。 |
| 申报/办理分离 | 任务行带 `permission_code`（域→权限映射 `DeathLinkageConstants.GetRequiredPermission`）；承接面按权限过滤可见可办；村级（VILLAGE_CLERK）矩阵不含 ELDERLY_EDIT/CHANGE_MANAGE/COLLEGE_MANAGE/RECOVERY_MANAGE → 村级申报后看不到任何承接面、联动卡禁用显示「需镇级办理」、首页横幅改"待镇级经办处理"文案。 |
| 失效随台账 | 申报 `Revoked/Archived/软删` → 所有任务行经 **JOIN 台账状态**自动退出列表/计数（不物理删、不单独取消）。 |
| 幂等两道闸 | ① `DeclareAsync` 成功后按申报ID补齐（失败仅告警不阻断申报）；② **任何列表/计数读取前按范围幂等补齐**（覆盖申报后身份才变化的漏任务 + 存量申报）。两闸共用 `EnsureLinkageTasksCoreAsync`（5 条域级 INSERT...SELECT）。 |
| 去重 | 身份证+域 且存在**有效申报**下的任务行（作废/归档的旧行不阻断重新申报后的新生成）；同人同域跨申报的重复行读取侧 `GroupBy(id_card, domain)` 取最新。 |
| 权限失败保守拒绝 | 权限查询异常一律按无权限处理（宁可禁用不放行越权）。 |

## 3. 表结构

`nc_biz_death_linkage_tasks`（权威定义 `Resources/Schema/death_declarations/database.yaml`；现网迁移 `docs/migrations/20261031_death_linkage_tasks.sql` 已执行）：

`id | declaration_id(FK) | deceased_id_card | deceased_name | task_domain | ref_application_id | ref_elderly_id | permission_code | status(Pending/Completed) | village_id | town_id | created_at | completed_at`

**五个任务域**（`DeathLinkageConstants.Domain*`，生成命中条件镜像联动卡语义）：

| task_domain | 中文 | 权限 | 生成命中（EXISTS） | live 已办（退出列表条件） |
|---|---|---|---|---|
| ElderlyStop | 高龄停发 | ELDERLY_EDIT | 高龄在享/草稿 | 无 Confirmed/Draft |
| ArchiveHead | 户主死亡变更 | CHANGE_MANAGE | 该人是档案户主 | 有 is_household_head 死亡登记 |
| ArchiveMember | 档案成员减员 | CHANGE_MANAGE | 是成员**且非户主**（头优先） | 有死亡登记 |
| College | 大学生退出 | COLLEGE_MANAGE | 在读 Studying | 无 Studying |
| Recovery | 追缴结案 | RECOVERY_MANAGE | 追缴 Draft | 无 Draft |

## 4. 承接面与门控

| 域 | 承接面（UI） | 门控 |
|---|---|---|
| ElderlyStop | **高龄待办列表第三 Tab「死亡待停发」**（PC `ElderlyPendingListPage` + 手机 `MobileElderlyPendingListPage`），办理→ElderlyStopPage 预填（同联动卡契约） | Tab `IsVisible=CanHandleDeathStop`（ELDERLY_EDIT）+ 办理命令双检 |
| ArchiveHead/Member | **保障对象动态管理 Hero 区「死亡待变更」**（PC `ChangePage` + 手机 `MobileChangePage`）：户主→死亡变更页预填全套 / 成员→本页载入走既有减员 | 区块 `HasDeathChangeTasks`（权限∧有任务）+ 命令双检 + **SubmitAsync 保存门控 CHANGE_MANAGE** |
| College | **大学生管理 Hero 区「死亡待退出登记」**（PC `CollegeStudentManagementPage`；手机无此页），去退出→变更页预填身份证（复用今年毕业路径） | `HasDeathCollegeTasks`（COLLEGE_MANAGE）+ 命令双检 |
| Recovery | 既有追缴 Draft 列表即承接面（不新建 UI） | RECOVERY_VIEW/MANAGE 既有 |
| 联动卡 | 死亡情况说明第⑤步卡片：`DeathLinkAction.CanHandle`（VM 加载时按 NavKey 权限批量判定）→ 无权限按钮禁用+文案「需镇级办理」；`OpenLinkAsync` 跳转前复核（缓存可能过期） | `DeathLinkageConstants.GetNavKeyPermission` |
| 首页横幅 | 计数=任务表 live 未办数（`GetLinkageTaskCountAsync`，先 ensure 再 count，DISTINCT(id_card,domain)）；文案按承接权限分流（有→"请前往办理"；无→"待镇级经办处理"） | `MainViewModel.DeadLinkageCanHandle` |
| **权限码** | `COLLEGE_MANAGE`（大学生管理）：PermissionSeedCatalog 定义+矩阵授予 SUPER/COUNTY/TOWN_ADMIN+TOWN_CLERK，**村级无**；`MatrixVersion 4→5` 启动自动重建（已实测入库） | 大学页入口双门控（SocialAssistanceHome 卡 + MainViewModel 导航） |

**目标页堵洞**（修复前三页零权限校验，村级可经跳转直接办镇级手续）：
- `ElderlyStopViewModel.ConfirmStopAsync` → 保存前 ELDERLY_EDIT；
- `HouseholdDeathChangeViewModel.SubmitAsync` → 提交前 CHANGE_MANAGE；
- ChangePage/大学页 入口门（CHANGE_VIEW/COLLEGE_MANAGE）已存在于上游导航。
