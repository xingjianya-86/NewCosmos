# 临时救助 C 线：申请日期归属恢复按验收日滚月

> 2026-10-20。修复 2026-10-18 C 线重构遗留的归属回归；
> 权威实现 `Services\Utilities\BusinessTimelineService.cs`（`CalculateCLineForApplyDate`），
> 上游节点口径见 `docs\20261018_临时救助C线时间轴口径.md`（§1/§3/§6 已按本文同步）。

## 1. 现象

2026-10-14 之后（尤其是 10-18 构建之后）新建临时救助：今天已是 10-20，表单却把申请日期回填成
**10-08**，公示日期固定在 **10-10~10-12**、验收日 **10-13** —— 归属被死死压在本月，且申请日期被改写了 12 天。

## 2. 根因

10-18 重构为了"申请日锚定、取消滚月"，把服务层的**向前滚月**删成了直接取申请日所在月：

```csharp
private TimelineResult CalculateCLineForApplyDate(DateTime applyDate)
    => CalculateCLine(applyDate.Date.Year, applyDate.Date.Month);   // 不滚月
```

表单 `ApplyPublicizeDefaultsAsync` 又对超出"申请上界 A−5"的日期做**回填钳制**（钳到 10-08），
于是"归属月固定本月 + 申请日期往回改"同时发生。而 `GetCurrentTempReliefCore` / `GetForDateCore`
仍是按验收日滚月的（今天 → 11 月），同一服务两条口径自相矛盾。

## 3. 决策（2026-10-20 拍板）

| 项 | 口径 |
|---|---|
| 归属边界 | **验收日 A（每月 13 号，非工作日顺延）**：申请日 ≤ A 归当月批次，超过 A 顺延下月 |
| 跨年 | 顺延自动接续到次年 1 月（实现内最多防御性顺延 24 个月，仍不满足回退申请日所在月） |
| 申请日期 | **原样保留，不回填、不钳制**；仅"晚于今天"的未来日期被拉回今天 |
| 公示/验收/调查窗口 | 取**归属月**的 C 线窗口（验收日 A、公示 A−3~A−1、调查 [A−5, A−3]） |
| 可见性 | 表单申请日期下方显示"本次归属：{年}年{月}批次（公示 …~…，验收 …）"；编辑/查看已存档案不显示 |
| 补打/批量 C 线窗口 | **维持 `(上月验收日, 本月验收日]` 不变** —— 它恰好等于"归入本月批次的全部申请日区间"，与 A 口径无缝无重叠（改用 [A−5, A] 反而会漏掉 A−5~A 这 5 天） |

**边界提示**：申请日落在 A−5 ~ A（本月 09~13 号）仍归本月，该窗口内本月公示期已开始或已过，
打印出的公示起止会早于申请日期。如业务上不接受，改一处比较即可切回 A−5 口径（见 §5）。

## 5. 口径开关（如需改边界）

`CalculateCLineForApplyDate` 中把

```csharp
if (date <= line.AuditDate.Date)   return line;   // 现行：验收日 A
```

改成 `if (date <= line.InvestigationStartDate.Date)` 即切到 **A−5（上界 = 调查窗口起日）**：
10-09 起即归下月，可消除 §3 的边界问题，但补打批次窗口须同步改为 `(上月 A−5, 本月 A−5]`，
否则这 5 天的档案会落到上一批。**改前必须一并评估这两处。**

## 6. 存量数据核对（只查不改，人工处置）

本回归自 10-18 构建生效，此前"钳到 A−5"会把 10-14 之后录入的申请日期写成 10-08。
**草稿**重开会自愈（读草稿时申请日期重置为今天 → 按 A 重新归属）；**已确认档案**需人工核对：

```sql
SELECT id, application_no, applicant_name, apply_date,
       publicize_start_date, publicize_end_date, status, created_at
FROM nc_biz_temp_relief_applications
WHERE deleted_at IS NULL
  AND created_at >= '2026-10-18'
  AND apply_date = '2026-10-08'
ORDER BY created_at DESC;
```

命中且已确认的，按真实受理日手工改 `apply_date`（`apply_year` 仍为 2026，不影响"每年一次"限制）。
