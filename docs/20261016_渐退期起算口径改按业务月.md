# 渐退期起算口径改按业务月 + 卢永华（档案80）数据修正

> 日期：2026-10-16。代码改动 5 文件（见 §3）；数据改动仅 1 条 UPDATE（单事务带守卫，可回滚，见 §4）。
> 原值备份与脚本：`backup\20261016_095201_卢永华渐退期起算口径修复\`（`orig_grace8.txt` / `fix.sql` / `check.sql`）。

## 1. 问题与规则

**症状**：卢永华（档案80，户主樊万河68死亡停旧建新，低保→低保边缘触发渐退）属 **2026-10 业务**
（B线周期 `[2026-09-21, 2026-10-20]`，登记 09-25、办结 10-09 均在周期内），但库中渐退期是
**2026-10-01 ~ 2027-03-31**，早了一个月。

**正确口径（本次固化）**：渐退期起算日 = **业务所属月份（B线归属月）的次月 1 日**，结束日 = 起算日 + N月 − 1天。
本例 → **2026-11-01 ~ 2027-04-30**（6 个月）。

## 2. 根因

`ClassificationService.CheckGracePeriodEligibility`、`GracePeriodService.CheckEligibility`/`SetGracePeriod`
三处各自写同一公式，且起算锚点是 `DateTime.Today` 的**日历月**：

```csharp
var today = DateTime.Today;
var nextMonth = new DateTime(today.Year, today.Month, 1).AddMonths(1);
```

与业务所属月份（月报统计口径）无关。档案80 的 Step5 首判发生在 2026-09-25（日历9月）→ 起算冻成 10-01；
10-09 的分类施保金额修复（`docs\20261009_户主死亡渐退分类施保减发修复.md`）只改金额未动日期，错值沿用至今。

另发现同族隐藏缺陷：表单保存兜底 `ApplicationFormViewModel.SyncGracePeriodRecordAsync` 用
`start = 今天所在日历月的1日`（**当月**，非次月），与判定/确认两处口径均不同——一并收敛。

| 文件 | 改动 |

| `Services\Domain\SocialAssistance\ClassificationService.cs` | 注入 `IBusinessTimelineService`；`CheckGracePeriodEligibility` 改为先取 B 线归属月（`GetTimelineForDate(Today, BusinessProcess)`）再走单点 |
| `Services\Domain\SocialAssistance\GracePeriodService.cs` | 注入 `IBusinessTimelineService`；新增私有 `CalculatePeriodCore`（本服务唯一取数入口），`CheckEligibility`/`SetGracePeriod` 改走它；新增公开 `CalculatePeriod(months)` |
| `Services\Domain\SocialAssistance\IGracePeriodService.cs` | 接口新增 `GracePeriodInfo CalculatePeriod(int months)` |
| `ViewModels\SocialAssistance\ApplicationFormViewModel.ClassificationAndSave.cs` | 保存兜底改调 `CalculatePeriod`，删除自算的"当月1日"公式 |

- 业务归属月取自 `BusinessTimelineService`（周期含结算日遇法定节假日提前，`BCycleSettleDay` 取自 `app.ini`），
  **与月报统计同源**，不另造周期口径。
- 全部命中渐退期的下游（Step5 确认页、变更 `ReconcileGracePeriodAsync`、`ApplyGracePeriod` 两处）均读
  `classificationResult.GracePeriod.StartDate`，自动随新规则生效，无需改动。
- DI：三个服务均 Singleton，`BusinessTimelineService` 仅依赖 `IHolidayService`/`ILoggerService`，无环。

## 6. 遗留观察（未处理，不属本批范围）

1. **复核会覆盖在效渐退期起止日**：`ChangeService.RebuildAndReview.ReconcileGracePeriodAsync` 命中即
   `ActivateAsync` 覆盖日期——经济复核/家庭成员变更重判会把在效渐退期整体后移（12月复核 → 变成 01-01~06-30，
   等于"续命"）。本批仅改起算锚点，未改此语义；是否应"已有在效记录且仍符合时保留原起止日、只更新金额"
   需业务确认后另行处理。
2. Step5 确认页仅可选月数、不可改起算年月；若将来需要人工调整，应在确认页加起算年月选择并写入单点。
