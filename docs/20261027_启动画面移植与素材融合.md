# 启动画面移植与素材融合（dsh-startup-screen → 帝皇权杖δ-me13）

> 2026-10-27。启动首屏由"白底转圈过渡页"改为 dsh-startup-screen 二次开发版动画：
> 黑幕品牌 → 过曝洗白 → 暖白「技术档案」底板 → 五步授权序列 → 色散故障揭幕，
> 揭幕时露出登录页同源背景图，随后无缝切到真实登录页 / 主界面。

## 1. 运行链路（双就绪门）

```
CreateWindow
 ├─ window.Page = SplashPage（WebView 播放动画，右上角 SKIP / Esc 可跳过）
 └─ RestoreSessionAndNavigateAsync（照旧：本地会话 → DB 校验 → 心跳）
        └─ 所有出口（主页 / 登录页 / 连接重试页）先 await ISplashGate.WhenCompleted
SplashPage 结束 → ISplashGate.Complete()
        ↑ 动画播完 / 跳过 / 脚本异常 / 超时看门狗（默认 40s）
```

- 会话恢复与动画**并行**：数据库快也不会掐断动画，动画长也不会推迟登录校验的结论。
- 关掉动画（`SplashEnabled=0`）即回到原来的白底"正在启动…"过渡页，行为与改动前一致。

## 3. 为什么用 https 虚拟主机而不是 file://

动画运行时用 `fetch('audio/line-1.mp3')` 取素材再 `decodeAudioData` 播放。
`fetch` 在 `file://` 下会被浏览器直接拒绝（这是上游 `preview` 也必须走 http 服务的原因），
所以两端统一用虚拟主机 `https://splash.newcosmos.local/`：

- **Windows**：`SplashAssetsService` 把构建输出 `splash\` 同步到 `%AppData%\NewCosmos\Splash\`
  （程序装在 Program Files 时输出目录只读），每次启动重写 `config.js` 与 `img/bg.webp`；
  `SplashPage` 用 WebView2 `SetVirtualHostNameToFolderMapping` 映射该目录。
- **Android**：`SplashWebViewClient.ShouldInterceptRequest` 直接返回 `assets/splash/` 内容，
  `config.js` 与 `img/bg.webp` 由内存/AppData 即时提供，不落盘。

## 5. 配置（`config\app.ini`）

```ini
[Splash]
SplashEnabled=1              # 0 = 关闭动画，回落白底过渡页
SplashSound=1                # 0 = 静音（台词 + 音效），纯视觉
SplashSpeed=1.0              # 0.35–3
SplashRequireInteraction=0   # 1 = 第 1、2 步要点按钮/回车才继续
SplashTimeoutSeconds=40      # 脚本异常兜底（10–180 秒）
```

> 注意：ini 解析忽略 section，键名全文件唯一即可；非法值回退默认并在 `app_.log` 告警。

## 6. 冒烟验证清单

1. 冷启动 → 动画播放（声音）→ SKIP/Esc → 登录页；
2. 已登录会话 → 动画与恢复并行 → 动画结束进主页；
3. 断网启动 → 动画结束后显示"暂时无法连接服务器"重试页；
4. `SplashEnabled=0` → 直接白底过渡页 → 登录页（行为与旧版一致）；
5. `SplashSound=0` → 无声音，动画节奏不变；
6. Android 真机：动画不白屏、台词能自动播放、揭幕后切页正常。
