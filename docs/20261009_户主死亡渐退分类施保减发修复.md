# 户主死亡进入渐退期：分类施保减发修复记录（樊万河→卢永华）

> 日期：2026-10-09。数据改动仅限文末列明的 4 条语句（3 UPDATE + 1 INSERT，单事务带守卫，可重复执行）。
> 脚本与原值备份：`backup\20261009_161039_樊万河死亡渐退分类施保减发修复\`（orig_*.txt 原值 / fix_*.sql 修复 / check_*.sql 核对）。

## 1. 背景与规则

樊万河（档案68，农村低保，2人）死亡后停旧建新，新户主卢永华（档案80，1人）。Step5 判定收入
881元/人·月 超低保标准（632），进入渐退期（2026-10-01～2027-03-31，6个月）。

**业务规则**：渐退期内月保障金按原户月 313 元续发（封顶上限 632×1 未触发）；分类施保减去死亡
户主樊万河享受的份额 104 元、保留卢永华（66周岁高龄）的 104 元 → 新档应为 **313 + 104 = 417**。

## 3. 代码修改清单

1. **口径修复**：链上游原额改取 `HouseholdMonthlyGuaranteeAmount`；同步加载 `_originalClassifiedContext`（旧档分类施保）、`_originalHeadNameContext`（旧档户主名）、`_originalApplicationId`（链标记）。
2. **渐退分类施保**：两处 Step5 判定入口，渐退命中后对链档案预调 `CalculateClassifiedSubsidyAsync`（按原分类待遇对幸存成员重算）→ 确认页展示 → **确认才应用**（取消不写）；预估异常告警跳过、禁止按 0 写库。
3. **减发记录**：`IChangeService.EnsureChainClassifiedSubsidyReduceAsync`（幂等：金额一致跳过/变化更新/原额≤现额软删；`change_category=NULL`、无快照、`triggered_*=false`、`change_reason_type='分类施保减除'`——**故意不用"户主死亡"**，防 `GetLatestReviewChangeRecordAsync`/`GetLatestGraceExitChangeAsync` 按 reason_type 取最近一条时误读），挂点 `SaveClassificationResultAsync`（与 CategoryAdd 同批、失败仅告警）。
4. **P2 加固**：`EnsureChainCategoryAddAsync` 分类一致但金额漂移时同步 UPDATE（原"一致即跳过"盲区）。
5. **月报**：`GetShiBaoReductionRowsAsync` 增第二数据源——`change_records` 减发行，`changed_at` ∈ 本月 B 线周期；户主/地址/类别/原现户月取旧档、减发成员取死亡记录（缺失回退旧档户主）。
6. **话术四处**（按核定口径）：
   - 渐退保存提醒：月保障金 原→现（同额显"按原额发放"）+ 分类施保行（减去原户主X份额）+ 合计行 + 减发去向说明；
   - 渐退审批表「变动情况说明」：`月保障金313.00元无变化；分类施保由208.00元调整为104.00元`（原错例"由521调整为521"消除）；
   - 户主死亡变更成功提示：追加分类施保份额减发与月报去向；
   - 渐退期确认弹窗（桌面+手机）：新增"分类施保 208.00 → 104.00 元/月（减发 104.00 元）"行，原=现隐藏。

## 6. 遗留观察（未处理，不属本批范围）

1. **死亡链新档主表健康字段复制自旧户主**（`ExecuteHouseholdDeathAsync` INSERT-SELECT 未覆写
   health_status/disease/disability 等）：本例双方均"无任何疾病"未触发；若原户主带重病/重残标记，
   新户主的分类施保预估可能误判。建议后续在建档时按新户主成员行覆写。
2. **成员变更/经济复核链进入渐退**的分类施保由服务端重算（`RebuildAndReview` 门同为"低收入不算"），
   与本批 Step5 路径口径可能不一致；成员变更链的分类施保减发也未写减发记录（常量注释限定户主死亡）。
3. 渐退期满后新档按低收入重判，分类施保归 0 属预期；记录48 作为事件审计保留不回收（代码内置策略）。
