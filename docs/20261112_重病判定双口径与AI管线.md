# 重病判定双口径与 AI 建议管线

> 2026-11-12 定稿并落地（P0 服务端 / P1 客户端 / 轨二费用口径）。
> 权威入口见 AGENTS §14「重病判定」行；本文记录口径、架构、防线与运维，不复述代码。

## 一、判定口径（双口径）

### 1. 病种目录口径（AI 辅助）

- **目录权威**：`deploy\ocr\severe_disease_catalog.json`（服务端）与 `Resources\Icd10\severe_disease_catalog.json`（客户端副本）——**两份必须字节一致**，`notes` 内有同步约定。结构：`items`（清单项）+ `aliases`（别名）+ `code_ranges`（编码段）。
- **三条业务裁定（2026-11-11/12 拍板，改动须回改清单并重跑冒烟）**：
  1. 诊断只写"脑梗塞/脑梗死"（不带"急性"）**不算**重病——有一年恢复期；I63 刻意不入编码段表；
  2. "糖尿病"未分型**不算**——清单只有 I型糖尿病（E10）；
  3. "癌症待查"/未特指恶性肿瘤（C80.9）**算**——清单补"恶性肿瘤"条目 + 别名 + `C00-C99` 编码段三重覆盖。

### 2. 费用口径（纯规则，黑龙政办法第六十八条）

- 申请之日前 **12 个月个人累计自付**（住院+门诊慢特病+高值药品，经办人手工录入）**超过**上年度本地区居民人均可支配收入 → 重病患者；"超过"=严格大于，等于不算。
- 阈值：`nc_config_standards.standard_type='SevereDiseaseCostThreshold'`，按申请户口取档（`HukouType != Urban` 即农村档）：
  | 档位 | 值（2025 年数据） | 生效 |
  |---|---|---|
  | Rural | 29381 元/年 | 2026-01-01 起 |
  | Urban | 41757 元/年 | 2026-01-01 起 |
- 年度更新：标准配置管理页「重病费用口径阈值」分类改值（或改 `Resources\Seed\config_standards\seed.yaml` 后重灌种子），**禁止改代码硬编码**（§11）。阈值缺失/为0 → 不判定，降级人工。
- 规则单点：`Services\Domain\SevereDisease\SevereDiseaseByCostRule.cs`。

## 二、AI 建议管线（P0+P1）

```
编码命中 ICD 字典带出名称
  ① 客户端确定性（SevereDiseaseJudge：精确 → 单向包含（输入⊃清单项，禁止反向）→ 编码段 + 别名）
      命中 → 毫秒级建议/自动勾选，离线可用，不走网络
  ② 未命中 → 缓存 nc_sys_ai_judgments（键=规范化名称|编码 + policy_version=清单 sha256 前16位）
  ③ 未命中 → 服务端 POST /ai/severity（deploy\ocr，与 OCR 同服务同端点）
      服务端同样先确定性、再 qwen2.5:3b（prompt=全目录+反向禁令+正负例 few-shot，补测 v5 定稿）
      → 响应双侧校验 matched_item∈清单 → 写缓存（LLM 结果才缓存）
```

- **服务契约**：请求 `{name, code}`（name 必填，客户端先由编码带出名称）；响应 `verdict/matched_item/confidence/reason/source/auto_eligible/policy_version/model`。地址复用 `network.ini OcrServiceUrl`（同服务）。客户端超时 100s > 服务端 90s（服务端先报明确 502）。
- **触发入口（4+2）**：桌面 Step1/成员卡、移动 Step1/Step2（编码 TextChanged→字典命中→判定；LLM 路径 600ms 消抖，连续敲码只判最后一次）；费用字段（申请人失焦/成员 TextChanged）。
- **建议条**：同一根 UI 条（`AiSeveritySuggestionText`/成员 `AiSuggestionText`），仅 `verdict=severe` 或费用超阈值时显示；文案拼装点 `AiJudgeConstants.FormatSuggestion` / `SevereDiseaseByCostRule.FormatSuggestion`；点击忽略只隐藏，不动勾选。

### 自动预勾选安全策略（四道防线）

1. **闸门单点** `ISevereDiseaseAdviceService.ShouldAutoCheck`：`severe && matched_item∈清单 && 用户未否决`；费用口径用同一语义（规则成立 && 未否决）。
2. **只勾不取消**：AI/规则永不把 IsSevereDisease 从 true 改 false。
3. **人工否决即停**：true→false 只可能来自用户（加载恢复有 `_suppressSevereRejectTrack` 抑制），否决后本会话不再自动勾选；建议条仍可显示供参考。
4. **双侧响应校验**：服务端丢弃胡扯 matched_item，客户端 `NormalizeServerJudgment` 再校验一次；坏 verdict 降级 unknown。

- **审计**：`RemoteAiJudgeClient` 成功路径 `LogBusiness("AI 重病判定完成", verdict/matched_item/source/auto_eligible/code/elapsed)`——只记判定结论与编码，不记人员身份信息（§10）。
- **降级**：服务不可达/超时/解析失败 = 无建议（`Result.Failure` 显式上抛 + 用户友好文案），**不阻塞表单保存**；确定性层与缓存兜住常用输入。

## 五、运维与坑

- **政策改版**：改服务端清单（scp 到 `/opt/newcosmos-ocr/`，保存即热载）→ `policy_version` 自动变化失效客户端缓存 → **同步改客户端副本并随版本发布**（字节一致约定）。清单口径变更同步回改本文件「三条裁定」。
- **模型**：`qwen2.5:3b`（1.9G，`AI_MODEL` 环境变量）；1.5b 已删（常识压过目录指令，补测淘汰）。OCR/AI 同容器 `MAX_LOADED_MODELS=1`：OCR 用过后首次 AI 判定最坏 ~38s（重载+prompt 全量），由确定性层+缓存+异步建议条兜住。
- **资源**：ollama mem 3G 下 3b 驻留实测 2.17G；热态判定 4-6s，确定性 1-15ms。
- **踩坑记录**：
  - PowerShell 管道给原生命令默认 ASCII → 中文全变 `?`：先 `$OutputEncoding=[System.Text.UTF8Encoding]::new($false)`；
  - Windows OpenSSH 转义 argv 反斜杠 → `tr -d "\r"` 变成删字母 r：远端循环用"ASCII 脚本经 stdin"传；
  - xUnit `InlineData` 不能直接吃 int→`decimal?`、C# 特性实参不收 decimal：改 Fact 直写。
