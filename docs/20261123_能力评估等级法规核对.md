# 能力评估等级：法规核对与代码审计（2026-11-23）

> 触发：用户反馈「能力评估貌似只有三个级别」。
> **最终决策（2026-11-23）：对外统一采用黑民规 3 档（自理 / 半自理 / 不能自理），
> 照料护理档次采用黑民规第四十五条 3 档（全自理 / 半护理 / 全护理）。**
> 5 档内部评分与 4 档历史照料等级仅保留用于计算/兼容，只在详情里标注展示。
> 原 C# 系统在档案输出时用 `CapabilityLevel.ToSelfCareDisplay` 做 5→3 归并，Rust 首次移植漏掉了这一步；
> 本次已补齐，并修复了页面「上下床」开关的字段名错位。

## 1. 用户看到「3 个级别」的真实原因

| 编号 | 事实 | 证据 |
|---|---|---|
| R1 | **改造前** Rust 后端元数据返回 **5 个自理等级 + 4 个照料等级**，页面下拉、列表、筛选、Excel 均取这组常量，没有任何 3 档截断 | `crates/nc-core/src/capability_assessment.rs` `SELF_CARE_LEVELS` / `CARE_LEVELS`；`capability_assessment_meta()`；`CapabilityAssessmentView.vue` 的 `v-for="item in selfCareLevels"` |
| R2 | 原 C# 系统本身就有**两套口径**：5 档内部评分 + 3 档档案输出 | `Constants/DictionaryConstants.cs` `CapabilityLevel.All`（5 档）与 `ToSelfCareDisplay`（自理/半自理/不能自理） |
| R3 | C# 的 3 档只用于**档案文书字段**「自理能力评估」，不在能力评估页面显示 | `ViewModels/ArchiveManagement/ArchiveProductionViewModel.DocumentFields.cs::BuildSelfCareAbility` |
| R4 | Rust 移植时**只移植了 5 档**，没有移植 `ToSelfCareDisplay` | 全仓检索无 3 档常量/函数；页面只有「自理能力等级」一列 |
| R5 | **真实 bug**：页面「上下床」开关用 `nc-core::ITEMS[].key`（原为 `gettingInOutOfBed`）索引表单，但表单/DTO 字段是 `gettingInOutBed`，导致该开关永远读不到表单值、点击也写不回 | `CapabilityAssessmentView.vue` `itemValue(item.key)`；`AssessmentForm.gettingInOutBed`；`CapabilityAssessmentInput.getting_in_out_bed` |
| R6 | R5 的后果：开关显示「不能」时后端仍按「能」计 1 项；`完全失能`（0/6）无法从页面评出，且「显示」与「结论」自相矛盾 | 同上；`level_for_count(0)` 只能由全 0 触发 |

因此：
- **不是 UI 只渲染了 3 个选项**（改造前选项确为 5 个）。
- 用户说的「3 个级别」来自特困法定 3 档 / C# 档案输出的 3 档（R2、R3），而 Rust 页面缺少这一层，只剩 5 档内部标签；
  R5 又把可评范围截断（完全失能不可达），进一步强化了「级别不全」的观感。
- **最终按用户决策改为对外 3 档**（见 §4）：页面主列、筛选、结论、Excel 全部用 3 档；
  5 档只在详情里作为「细分等级」保留。

## 3. 两套口径的精确映射（最终采用 3 档对外）

设「能完成项数」= C（0-6），「不能完成项数」= 6 − C。

| C（能完成） | 对外 3 档自理 | 照料护理 3 档（黑民规第45条） | 5 档内部细分（仅详情） | 不能项 |
|---|---|---|---|---|
| 6 | 自理 | 全自理 | 全自理 | 0 |
| 5 | 半自理 | 半护理 | 轻度失能 | 1 |
| 4 | 半自理 | 半护理 | 中度失能 | 2 |
| 3 | 半自理 | 半护理 | 中度失能 | 3 |
| 2 | 不能自理 | 全护理 | 重度失能 | 4 |
| 1 | 不能自理 | 全护理 | 重度失能 | 5 |
| 0 | 不能自理 | 全护理 | 完全失能 | 6 |

5 档只是把 3 档的「半自理」细分为轻度/中度、把「不能自理」细分为重度/完全，
**不是两套互相矛盾的结论**；因此 `level_for_count` 保留 5 档用于计算与历史快照，对外展示/筛选/导出一律走 3 档。

### 4.2 照料等级派生与历史数据

- `statutory_care_level` **不落库**，由 `self_care_level`（5 档）实时派生：
  全自理→全自理；轻度/中度→半护理；重度/完全→全护理。
- 数据库 `care_level` 列仍是旧的 4 档快照，**不回写、不批量更新**；保存时仍按 C# 兼容语义写入 4 档快照
  （`self_care_level` 仍写 5 档），但展示与导出一律用派生 3 档，避免把 3 档值混进历史列。
- 详情页把旧 4 档标注为「旧 4 档口径（按六项重算，仅兼容展示）」；该值由六项原始值重算，不读取库内快照列。

  `ViewModels/ArchiveManagement/ArchiveProductionViewModel.DocumentFields.cs`。
