## 1. 变更摘要

1. **移除**录入页顶部「选择已有备案」下拉；改为**输入工作人员身份证号满 18 位自动处理**：
   - 该身份证已有有效备案 → 自动载入编辑（表单已有内容先弹确认，替换原下拉职责）；
   - 未备案但命中系统用户表（`nc_sys_users`） → 带出经办人员工作信息（姓名/联系方式/工作单位=机构名/职务/乡镇=机构所属乡镇），可继续修改。
2. **救助对象信息从档案读取（一一对应）**：对象行身份证号满 18 位自动查本系统申请表 `nc_biz_applications`，
   带出档案数据并**锁定只读**，同时回填 `application_id`（档案输出/月报与申请一一对应）。
   - 取值顺序：在享（Approved/Completed）优先，其次最新一条（草稿/已停保也返回，来源提示含状态）；
   - 多命中：取上述规则第一条，状态栏提示「申请 编号（日期，状态）」；
   - 未命中：提示"未在本系统档案中找到该身份证的救助申请，请手工录入"，该行保持手工可编辑；
   - 命中但已被其他工作人员备案：带出并提示占用方姓名（保存时仍会被归属校验拦截）。
3. **工作流卡片入口**（申请卡片「近亲属备案」）：按申请ID完整带出对象行（原仅带姓名/身份证）。
4. **编辑载入按档案刷新**：已保存备案再次打开时，已关联申请的对象行自动重新拉取档案数据并覆盖档案字段
   （状态栏提示"已按档案刷新 N 行"；未命中/失败保留原值不阻断）。
5. **文案更正**：「报账金额」→「**保障金额**」（页面标签、字段键注释、Schema 注释、实体注释；字段键与列名 `report_amount` 不变）。
6. **列表页「输出档案」**（第二批）：备案行进入档案输出页「近亲属备案独立输出」域——仅两张档案表
   （工作人员关联信息表 / 救助对象信息表）、每对一页；无"完成归档/完成工单"语义（按钮隐藏+命令兜底）；
   打印留痕 `business_type=NearRelative`（复用 `PRINT_FAMILYAPPLICATION` 权限），输出落 `{输出根}\近亲属备案\{日期}\{工作人员_身份证}\`。
7. **补打断链修复**（第二批）：近亲属对数据此前只在档案制作页导航时写入静态上下文（`PrepareAndNavigateAsync`），
   补打中心与文书直出**未显式携带** → 补打近亲属两表行数据为空。现改为
   `ApplicationPrintData.NearRelativePairs` → `ReprintArchivePayload.NearRelativePairs`（可选参数）→
   `ApplyArchivePayloadToNav`/批量逐户显式写入 `PrintNavigationData.NearRelativePairs`；
   装配端每次先清空，防批量逐户残留上一户对数据。
8. **保障金额供给**（第二批）：档案救助对象信息表补 `NEAR_RELATIVE_REPORT_AMOUNT`、月报批量表补
   `NEAR_RELATIVE_REPORT_AMOUNT_{1..5}` 槽位供给（汇总表原本已供给）。
9. **模板本体更正**（2026-10-17，DB 直改并留备份；应用侧配合 `NEAR_RELATIVE_SUMMARY_RESIDENCE` 新键+供给）：
   - 152《档案_近亲属_救助对象信息表》：占位符"户主月保证金"→"**户主月保障金**"（config+单元格）；
   - 154《月报_近亲属_工作人员批量汇总表》：占位符"救助报账金额"→"**救助保障金额**"（9 组）；
   - 154"居住地址"列复制粘贴错误（原挂 `{救助身份证号N}`，会把身份证号打到居住地址列）→ 改为 `{救助居住地址N}`（xlsx H5:H13 + config 9 组映射）；
   - 更正前快照：`backup_20261017_nearrelative_templates`；迁移记录：`docs\migrations\20261017_nearrelative_template_corrections.sql`。

## 2. 申请表 → 对象行字段映射（单点实现：`NearRelativeService.MapApplicationToLink`）

| 对象行字段 | 申请表列 | 锁定 |
|---|---|---|
| 关联申请ID | `id`（自动） | ✅ |
| 姓名 / 身份证号 / 性别 | `applicant_name` / `applicant_id_card` / `gender` | ✅ |
| 出生年月 | 身份证解析（`IdCardValidator.ExtractBirthDate` → `yyyy年M月`） | ✅ |
| 户籍地址 | `hukou_address` | ✅ |
| 居住地址 / 家庭住址 | `town + community + address` 拼接（暂同源） | ✅ |
| 家庭人口 | `family_size`（为 0 时取 `confirmed_family_size`） | ✅ |
| 社会救助种类/保障类别 | `classification_result` → `ClassificationConstants.ConvertFromCode` | ✅ |
| 月保障金 | `household_monthly_guarantee_amount` | ✅ |
| 保障金额（原"报账金额"） | `total_guarantee_amount` | ✅ |
| 救助起始时间 | `first_approved_at` → `yyyy年M月` | ✅ |
| 申请原因 | `application_reason_detail` 优先，空则 `application_reason` 字典显示 | ✅ |
| 申请时间 | `submit_at`（有效时）否则 `created_at` → `yyyy年M月d日` | ✅ |
| 与工作人员关系 / 家庭关系 / 家庭主要困难 / 经济调查 / 乡镇意见 / 动态记录 | 无档案来源，**保持手工录入**（不锁定） | — |

## 3. 锁定与解锁

- 锁定判定：对象行 `IsArchiveLinked=true`（由 `application_id` 关联驱动），档案来源字段 `IsReadOnly` 绑定；
- 行头显示来源徽标「已关联：申请 编号（日期，状态）」；
- 「解除关联」按钮：保留当前值转为手工可编辑（清空关联申请ID），用于纠错重录。

## 4. 服务接口新增（`INearRelativeService`）

| 方法 | 用途 |
|---|---|
| `GetByStaffIdCardAsync` | 按工作人员身份证查已有有效备案（含对象明细），录入页自动载入 |
| `GetStaffWorkInfoByIdCardAsync` | 按身份证检索工作信息：`nc_sys_users`（JOIN 机构/乡镇）优先，档案照料护理人补空（`nc_biz_caregivers` → `nc_biz_destitute_persons.caregiver_id_card`）；见 §9 |
| `BuildLinkByIdCardAsync` | 按救助对象身份证查最新申请表并映射为对象行（含占用检查） |
| `BuildLinkByApplicationAsync` | 按申请ID映射对象行（工作流卡片入口 / 行重新读取） |
| `RefreshLinksFromArchiveAsync` | 批量按申请ID刷新映射（`= ANY($1)` 防 N+1） |

## 5. 输出备案档案（列表页入口，第二批）

- **入口**：近亲属备案列表页 → 行「输出档案」按钮（权限 `NEAR_RELATIVE_MANAGE`）。
- **装配**：`GetByIdAsync` → `FlattenPairs` → 逐对 `BuildArchivePairFields`（审核时间=当前 B 线审核日）→
  写 `PrintNavigationData`：`BusinessType=NearRelative`、`BusinessId=备案ID`、`NEAR_RELATIVE_HAS_DATA=1`、
  `APPLICANT_NAME/ID_CARD=工作人员`（打印记录与输出目录主体）、`NearRelativePairs=对数据`；文书模式四字段先清零。
- **模板获取**：输出页对 `NearRelative` 域**按模板名直取**两张表（`GetByNameAsync`，不依赖分类集）；未上传时明确提示模板名。
- **按钮语义**：完成归档/完成工单均隐藏（命令侧兜底拦截"无归档语义"）。
- **权限与目录**：打印权限复用 `PRINT_FAMILYAPPLICATION`（不新增权限种子）；
  输出目录中文分类名 = 近亲属备案（`OutputPathHelper.GetCategoryDisplayName`）。
- **补打/文书直出**：`ReprintArchivePayload.NearRelativePairs` 显式携带（见 §1.7），补打中心两表"每对一页"恢复正确输出。

## 7. 冒烟验证路径

1. 模块首页 → 近亲属备案 → 新增备案 → 输入经办人身份证（系统用户且已填身份证/职务/机构）→ 自动带出工作信息；
2. 输入已有备案的经办人身份证 → 自动载入编辑模式（表单有内容先弹确认）；
3. 对象行输入身份证（该户主在本系统有申请）→ 档案字段带出并锁定 + 显示关联申请编号 → 保存；
4. 业务申请工作流 → 任一申请卡片「近亲属备案」→ 打开即完整带出对象行；
5. 再次打开该备案 → 状态栏提示"已按档案刷新 N 行"；
6. 月报「近亲属备案（工作人员批量）/（汇总）」与档案制作近亲属两表打印字段正常；
7. 输入无本系统申请的身份证 → 提示未找到、保持手工录入可保存；
8. 无权限账号在列表页操作 → 仍提示无权限；
9. **列表页「输出档案」→ 输出页仅两张近亲属表 → 预览"每对一页" → 保存落 `{输出根}\近亲属备案\...` → 无"完成归档"按钮**；
10. **补打中心 → 低收入人口记录 → 输出近亲属两表 → 行数据完整（每对一页）**；
11. 申请档案制作 → 输出两表照旧（回归）。

## 9. 工作人员带出来源扩展：系统用户 + 档案照料护理人（2026-10-17 追加）

> 背景：经办人员（村/社区干部等）常无系统账号，但可能以"照料护理人"身份存在于救助档案中；原实现只查 `nc_sys_users`。

1. **检索来源与优先级**（`GetStaffWorkInfoByIdCardAsync`，录入页工作人员身份证满 18 位自动触发；已有备案载入逻辑不变）：
   - ① 系统用户 `nc_sys_users`（启用用户，JOIN 机构/乡镇）——优先，全量覆盖姓名/联系方式/工作单位/职务/乡镇；
   - ② 申请档案照料人 `nc_biz_caregivers`（JOIN `nc_biz_applications` 取档案乡镇；在享 Approved/Completed 优先，其次最新一条）——逐字段补空；
   - ③ 特困历史档案照料人 `nc_biz_destitute_persons.caregiver_id_card`（LEFT JOIN 家庭表取街道）——仅姓名/乡镇，逐字段补空。
   - 任一来源查询失败 → 整体显式失败（§7）；全部未命中 → 返回 null，界面提示手工填写（不覆盖已填字段）。
2. **界面提示**（状态栏）：
   - 用户+照料人均命中：`已从系统用户带出经办人员工作信息（X）；档案照料护理人另有记录，已补齐空缺信息`
   - 仅用户：`已从系统用户带出经办人员工作信息（X）`
   - 仅照料人：`已从档案照料护理人带出工作信息（X）`
   - 都未命中：`未在系统用户及档案照料护理人中找到该身份证，请手工填写工作信息`
3. **索引**（Schema YAML 增补 + 手写迁移 `docs\migrations\20261017_nearrelative_staff_lookup_indexes.sql`；无列结构变更）：
   - `nc_biz_caregivers.id_card` → `idx_caregivers_id_card`
   - `nc_biz_destitute_persons.caregiver_id_card` → `idx_destitute_persons_caregiver_id_card`
   - `nc_sys_users.identity_card` → `idx_nc_sys_users_identity_card`
   - 补建途径：执行迁移 SQL，或在「数据库管理 → 初始化数据库结构」由 SchemaService 幂等补建（启动不自动执行）。
4. **冒烟路径（追加）**：
   - 新增备案 → 输入 杨志华（尾号 4931，仅 `nc_biz_caregivers` 命中）→ 带出 姓名/电话/榆树村委会/柳树镇，状态栏标注档案照料护理人；
   - 输入 姜绪国（尾号 5630，仅特困历史档案命中）→ 带出姓名+柳树镇；
   - 输入系统用户身份证 → 用户信息为主、照料人补空；
   - 输入无来源身份证 → 提示未找到、可手工保存；
   - 回归：已有备案身份证 → 仍直接载入编辑；编辑载入不触发重复查询；软删照料人（deleted_at 非空）不命中。
