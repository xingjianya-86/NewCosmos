# 特困照料护理费计算与协议模板字段规范（20261015）

> 本文记录本批改动的业务口径与数据流，供后续维护对照。可执行逻辑一律以指向的源文件为准。

## 1. 照料护理费计算（公式单点）

**公式**（《牡丹江市低收入人口认定实施细则》第四十五条 + 黑政规〔2025〕1号）：

```
照料护理费 = 当地月最低工资 ÷ 10（全自理） / ÷ 6（半护理） / ÷ 4（全护理）
取整 = 四舍五入到元（MidpointRounding.AwayFromZero）
```

林口县适用第三档 1910 元/月 → **191 / 318 / 478**。

**数据流**：

| 环节 | 位置 | 说明 |
|---|---|---|
| 公式唯一实现 | `Constants\WageStandardConstants.cs`（`ComputeCareAllowance` + 三个除数常量） | 全库唯一，禁止别处重抄 |
| 档位解析 | 同文件 `ResolveLevelType(district)` | 按 `nc_biz_applications.district` 映射 MinWageLevel1/2/3 |
| 计算入口 | `ClassificationService.CalculateCareAllowanceAsync` | 公式优先；最低工资配置缺失时回退固定 `CaregiverAllowance*`（现值 191/318/478，已对齐公式） |
| 配置公示 | 标准配置管理页「照料护理费」分类横幅 | 展示公式 + 三档最低工资实时计算结果，改配置即跟随 |
| 协议输出 | `ArchiveProductionViewModel`（`ResolveCareAllowanceForPrintAsync`，主路径与分步路径均走） | 特困+分散供养+有能力鉴定时**实时计算**（不读落库旧值），否则回退落库值；**不写库**（AGENTS §9.7） |
| 配置数据 | `nc_config_standards` | `MinWageLevel1/2/3` = 2270/2010/1910；`CaregiverAllowanceFull/Partial/None` 降级为回退值 |

**保障金额参考**（已有配置，本批未改）：农村特困分散供养 822、城市 1076（`RuralDestituteStandard`/`UrbanDestituteStandard`，2026-08-12 起）。

## 2. 三张特困模板字段口径

## 5. 冒烟验证路径

1. 模块首页 → 近亲属备案：列表加载、搜索、新增/编辑/删除（无权限账号应弹提示）。
2. 业务申请工作流 → 任一申请卡片「近亲属备案」→ 录入页状态栏显示"已关联申请 #… 户主 …"，保存后档案输出能检索到该申请的关联备案。
3. 标准配置管理 → 照料护理费分类：公示横幅显示公式与三档实时值；改 MinWageLevel3 后重新进入应刷新。
4. 档案制作 → 特困档案：
   - 入户调查表预览：`{保障类型}` 勾选式、`{自理能力情况}` 六项明细；
   - 照料服务协议预览：文本框内县/镇/承诺时间有值、`{经办人}`/职务/身份证有值、协议期起=当天、止=12月31日、护理费=公式值（1910→191/318/478）、大写金额正确、银行卡号=Step5 录入值；
   - 分散供养协议：`{审核确认时间}` 形如 `2026年10月15日`。
5. 变更流程（成员变更/停旧建新）：照料人银行卡字段随复制迁移（两处 INSERT 已补列）。
