# 登录会话与多端互踢规范

> 2026-10-23。权威实现：`Services\Domain\UserManagement\UserSessionService.cs`、`Services\Core\SessionHeartbeatService.cs`、`Services\Core\SessionLifecycleService.cs`、`Constants\SessionConstants.cs`。
> 本文说明行为口径与部署要点；状态/原因/策略编码一律以 `SessionConstants` 为准。

## 1. 为什么需要

原实现只在本机 `SecureStorage` 保存登录快照（7 天），数据库没有会话记录，导致：

- 同一账号可在多台桌面 + 手机同时在线，责任无法追溯；
- 被顶号的旧端下次启动仍可恢复；
- 启动校验遇到网络抖动就清本地会话，弱网用户被迫反复登录。

现在**数据库 `nc_sys_user_sessions` 是会话唯一事实来源**，本机缓存只用于免登录恢复。

## 2. 数据表

- YAML 权威定义：`Resources\Schema\system_sessions\database.yaml`
- 已部署库迁移：`docs\migrations\20261023_user_sessions.sql`（幂等）
- 首次登录时若表不存在，`UserSessionService` 会经 `SchemaSyncService` 按 YAML 自动建表；
  正式发版仍建议先执行迁移脚本，避免首次登录承担 DDL 开销。

关键列：`session_id(uuid)`、`user_id`、`device_id`、`device_kind(desktop|android)`、
`device_name`、`app_version`、`login_at`、`last_seen_at`、`expires_at`、`status`、
`end_reason`、`ended_by`、`ended_at`、`client_ip`。

所有时间由数据库 `now()` / `timestamptz` 产生与比较，客户端改系统时间不影响有效期。

## 3. 登录裁决（按端配额，默认）

1. 密码校验通过后，在事务内 `pg_advisory_xact_lock(user_id)`，同一账号并发登录串行化；
2. 关闭已过期的活动行；
3. 读取活动会话（`FOR UPDATE`）：
   - **同端离线行**（超过在线窗口无心跳）一律让位；
   - **同端在线行**保留 `配额-1` 条最新的，其余置 `replaced`；
   - **同一 `device_id`** 的旧会话无论配额都置 `replaced`；
   - 另一端（桌面 vs 移动）不受影响；
4. 插入新会话（`status=active`，`expires_at = now() + N 天`），`pg_notify` 通知被替换会话。

策略可通过 `nc_config_system_standards`（`category='session'`）调整，未配置时用代码默认值：

| config_key | 含义 | 默认 |
|---|---|---|
| `session.policy` | 1=按端配额 2=严格单会话 3=多端并存 | 1 |
| `session.max_desktop` | 桌面端配额 | 1 |
| `session.max_mobile` | 移动端配额 | 1 |
| `session.heartbeat_desktop` | 桌面心跳秒数 | 45 |
| `session.heartbeat_mobile` | 移动心跳秒数 | 90 |
| `session.online_window` | 在线判定窗口秒数 | 180 |
| `session.absolute_days` | 会话绝对有效期（天） | 7 |
| `session.grace_seconds` | 被顶号后的保存宽限秒数 | 30 |

> `config_value` 是 `NUMERIC(18,2)`，策略用数值编码；`nc_config_system_standards.id` 非自增，
> 如需调整请由管理员按现有最大 id 追加记录（默认值即"桌面 1 + 移动 1"，通常无需配置）。
> 改配置后最多 60 秒生效。

## 4. 运行期

- **心跳**：登录/恢复后启动。刷新 `last_seen_at`；影响行数为 0 时才判定失效。
- **网络失败不踢人**：查询失败只累计告警（首次与每 10 次记一条），恢复后继续。
- **被顶号/强制下线**：桌面提示后给 `grace_seconds`（默认 30 秒）保存时间再退出；
  移动端提示 3 秒后直接回登录页。宽限期内数据库写操作放行，宽限期后才由会话闸门拦截。
- **启动恢复**：本地缓存 → 用户存在且启用 → 数据库会话 `active` 且 `device_id` 匹配 → 进入首页。
- **弱网启动**：数据库不可用时显示"重试 / 重新登录"，**保留本地会话**，不再误清。
- **旧版本缓存**（无 `session_id`）：升级后首次启动要求重新登录一次，之后正常免登录。
- **记录清理**：终态（replaced/kicked/logout/expired）记录保留 90 天，每次登录最多每 12 小时清理一次。

## 5. 管理端

用户管理页头「在线会话」：

- `USER_VIEW` 可查看；`USER_MANAGE_STATUS` 可强制下线；
- 列表按数据范围过滤（非超管仅本组织边界，空集显示空列表）；
- 「全部下线」保留操作者当前会话；
- 以下安全操作联动吊销该用户活动会话：
  - 重置密码 / 停用 / 删除用户 → 全部端；
  - 本人修改密码 → 保留当前端，踢掉其他端；
  - 分配/移除角色 → 全部端（权限需重新加载）。

审计走 `ILoggerService.LogSecurity`，只记 UserId、SessionId、端类型与原因，不记密码。

## 6. 冒烟验证

1. 桌面 A 登录 → 桌面 B 同账号登录：A 收到提示，30 秒后回登录页；DB 中 A 行 `replaced`。
2. 桌面已登录 → 手机登录：两端并存（策略 1），会话列表各 1 条。
3. 手机再次登录：旧手机被替换，回前台后跳登录页。
4. 断网/关 ZeroTier：心跳失败只告警；恢复后继续使用；重启应用出现「重试」页且本地会话未被清除。
5. 管理端「下线」：目标端在一个心跳周期内退出，审计有记录。
6. 改密/停用/调整角色：目标用户相关会话失效。
7. 关闭应用 7 天内重开：免登录恢复；被别处顶过则要求重登。
8. 两台设备并发点登录：只产生一个 active 同端会话。

## 7. 已知边界

- 客户端直连 PostgreSQL，没有 API 层，因此**这套机制不是安全边界**：被改造的客户端仍可绕过。
  它的定位是防误操作、可审计、管理可控；强约束需等 API 网关/数据库代理。
- 宽限期内（默认 30 秒）旧端仍可保存数据，这是为防丢表单有意保留的窗口。
- `pg_notify` 已发出但当前未实现常驻监听，桌面感知延迟 = 心跳间隔（默认 45 秒）；
  后续可补常驻 `LISTEN nc_session_events`（专用长连接 + 断线重连）做到秒级。
