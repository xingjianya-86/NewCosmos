# 业务节点文书直出规范

> 更新：2026-09-24（P0-P3 修订）。适用：人员变动（增减员/成员死亡/户主死亡/户主变更）、经济复核、渐退期相关保存/变更节点。
> 单一事实来源：可执行逻辑以源文件为准；本文只保留规则与挂点索引。

---

## 1. 五步规范

```
① 写入三要素 → ② 取数单入口 → ③ 字段单点装配 → ④ 输出文书（Production→Output 分类+预勾选）→ ⑤ 入口分流
```

### ① 写入三要素（ChangeService 写 nc_biz_change_records 时）

| 要素 | 要求 | 标杆 |
|---|---|---|
| `change_category` | 人员变动类一律 `MemberChange`（`DictionaryConstants.ChangeCategory.MEMBER_CHANGE`） | 户主死亡/成员死亡/户主变更 `ChangeService.cs` |
| `change_reason` | 可解析格式 `动词: 姓名(身份证)`（增减员调整表减员槽解析） | `户主死亡: 张三(id) → 新户主 李四` |
| 金额回填 | UPDATE `old/new_guarantee_amount`、`new_application_id`（有新档时） | 成员死亡/户主死亡 |

FundChange（经济复核/渐退超限）另：`change_type=FundChange` + 同分类 + old>new 才进月报减发表。

### ② 取数单入口

`ChangeService.GetMemberChangeRecordsAsync(applicationId)`：

```sql
WHERE (application_id = $1 OR new_application_id = $1)
  AND deleted_at IS NULL
  AND (change_category = 'MemberChange'
       OR change_type IN ('HouseholdDeath','MemberDeath','MemberRemove','MemberAdd','HouseholdHeadChange'))
```

- 停旧建新：变更挂旧档，新档经 `new_application_id` 关联。
- 存量无 category 靠 `change_type` 兜底。**禁止**各流程另写取数 SQL。

### ③ 字段单点装配

`ArchiveProductionViewModel.BuildPrintDataAsync(applicationId)` —— ADJ_*/GP_*/GR_*/全套 FieldData 唯一装配点。**禁止**在 ViewModel/Service 重抄字段公式。

### ④ 输出文书（Production → Output，分类加载 + 预勾选）

**路径（已定）**：点「输出文书」→ **先进 ArchiveProductionPage**（带 ApplicationArchiveParameter / ApplicationReviewArchiveParameter）→ 用户点「档案输出」→ **ArchiveOutputPage**。

**上下文（进 Production 前写入 `PrintNavigationData`，`PrepareAndNavigateAsync` 不清理）**：

| 字段 | 含义 |
|---|---|
| `OutputCategories` | 模板分类集；文档模式 = `ArchiveCategoryResolver.DocumentOperationCategories` |
| `OperationOverride` | 传入 `GetRecordCategories` 的操作位（人员变更/户主变更/经济复核等） |
| `PrefilterTemplateNames` | 预勾选名单（列表仍展示分类内全部，仅控 IsSelected） |
| `TemplateFilter` | 强白名单（仅 DocumentSheetService 旁路直出时用；Production 路径不设） |

**Output 初始化**：
- `OutputCategories` 非空 → 用它替代默认 `[classification,"新增"]`
- `PrefilterTemplateNames` 非空 → 按名单设 `IsSelected`；**告知书若在列表中恒勾**
- 无 Prefilter 时默认全勾（现状）

**预勾选规则**：

| 上下文 | 预勾 | 条件 |
|---|---|---|
| **告知书** | `档案_变更告知书` | **恒选**（列表中必勾） |
| **档案类型补挂** | `档案_入户调查表` / `档案_特困入户调查表_特困人员` | 文档模式且 `classification` 非空（**恒勾**，按分类码选版） |
| 有人员变动 | `变更_增减员调整表` | `GetMemberChangeRecordsAsync` 非空 |
| 渐退核定 | `档案_渐退期审批表` | `IsInGracePeriod` |
| 有超限减发 | `档案_保障金减少` | `OriginalGuarantee > GraceGrant` |

**整档路径**（正常保存/补全/无渐退复核/三选一「整套档案」）：进 Production 前调 `ClearDocumentOutputContext()`（清 OutputCategories/Prefilter/OperationOverride/TemplateFilter）。

**分类树**：`TemplateCategoryProvider` 变更组已含 8 叶（经济复核/资金变更/人员变更/户主变更/档案_保障金减少/变更_增减员调整表/档案_渐退期审批表/档案_变更告知书）。运营在模板管理勾选叶子 Path 写入 `nc_biz_templates.categories`。

### ⑤ 入口分流

| 场景 | 出口 |
|---|---|
| 渐退保存（禁止整档完成归档） | 提醒弹窗 → `OpenDocumentProductionAsync`（预置上下文）→ Production → Output |
| Step5「输出文书」按钮 | 同上（Command 仍名 `ShowGraceDocumentSheetCommand`） |
| 成员变更 / 户主变更 成功 | **三选一**：整套档案（清上下文→Production）/ 仅出文书（预置上下文→Production）/ 稍后 |
| 经济复核 | 渐退或超限减发 → 预置上下文→Production；否则清上下文→整档 Production |
| 正常新增/补全归档 | 清上下文 → `ArchiveProductionPage` 整档（不改） |

`DocumentSheetService.OpenOutputAsync`（强白名单直推 Output）**保留为旁路**，当前主路径不再调用。

## 2. 模板名常量（`Constants\DocumentTemplateNames.cs`）

| 常量 | 值（须与 nc_biz_templates.name 一致） |
|---|---|
| `MemberChangeTable` | `变更_增减员调整表` |
| `GraceApproval` | `档案_渐退期审批表` |
| `GrantReduce` | `档案_保障金减少` |
| `ChangeNotice` | `档案_变更告知书` |

实机核对：`ITemplateService.GetByNameAsync`；不一致改常量或改库中模板名。

**分类集**：`ArchiveCategoryResolver.DocumentOperationCategories` = 上表 4 + 经济复核/资金变更/人员变更/户主变更。

**入户调查表补挂（跟档案类型挂钩）**：两张入户调查模板（`档案_入户调查表`、`档案_特困入户调查表_特困人员`）挂的是 12 个档案分类码，**不进**上面的变动分类集——分类码若并入会把整档 20 张灌进变动文书。改由 `ArchiveOutputViewModel` 文档模式按 `PrintNavigationData.Classification` 走 `GetByCategoriesAsync([classification])` 追加名称含「入户调查」的模板（TemplateId 去重），低保/边缘/刚性取档案版、特困取特困版，选哪张由模板 `categories` 决定；追加处恒勾（Prefilter 名单不含它也会强制勾选）。覆盖补打中心「变动文书」与变更流程「仅出文书」两处（同一 Output 初始化）。

## 3. 补打（需求4：按人整档 + 批量指定模板，两路都要）

- **`GetReprintDomainCategories("FamilyApplication")`** = 12 分类码 + `"新增"` + **`DocumentOperationCategories`**（并集）→ 批量「指定模板」下拉可选出 4 张变动文书。
- **按人整档列表**：`GetRecordCategories("FamilyApplication", classification, operationOverride)` —— 输出文书模式传 override 时并入 `DocumentOperationCategories`；普通新增默认仍 `[classification,"新增"]`（避免整档被变动模板淹没；Output 侧用 Prefilter 控制默认勾选）。
- 告知书仍可按名追加（`ArchiveOutputViewModel` 停保三重门 / Filter 模式白名单无条件加）。
- 验证：补打中心 → 低收入 → 按人选户 → 整档模板列表可见变动文书（挂对分类后）；批量指定模板下拉含 4 张 → 打印留痕。

## 4. 各流程挂点

| 流程 | 写入 | 出口挂点 |
|---|---|---|
| 户主死亡 | `ExecuteHouseholdDeathAsync`（category/reason/金额已齐） | Step5 渐退 → `OpenDocumentProductionAsync` |
| 成员死亡 | `ProcessMemberDeathAsync` | 成员变更保存分支（若单独入口另挂） |
| 户主变更 | `ExecuteHeadChangeAsync`（category+金额+NewApplicationId） | `HeadChangeViewModel` 成功后三选一 |
| 成员增/减 | `ExecuteMemberChangeAsync` | `ExecuteMemberChangeSaveAsync` 成功后三选一 |
| 经济复核 | `ExecuteEconomicReviewAsync`（FundChange） | `ExecuteReviewSaveAsync` 分流 |
| 渐退超限减发 | `CreateGraceCapFundChangeAsync`（幂等 FundChange） | 预勾「保障金减少」 |

## 5. 渐退期管理页（P0）

- count/data SQL 同口径：`is_active` + `end_date IS NOT NULL` + `status IN (Approved,Completed,Draft)`。
- data SQL：`start_date AS grace_period_start_date` / `end_date AS grace_period_end_date` 别名对齐实体；`$1::date` 统一日期计算。
- `LoadPageAsync` 失败 **显式 Alert + Warn**（禁止静默空列表）。
- `GracePeriodExpiringListViewModel.OnAppearing` **重置 PageIndex=1**（防 OFFSET 越界）。
- 实体补 `StartDate`/`EndDate` 兼容属性。

---

## 6. 禁止事项

1. 禁止在输出文书/过滤模式点「完成归档」或调用 `CompleteArchiveAsync`（渐退 Draft 会被误置 Approved）。
2. 禁止 Service 长期持有 `ArchiveProductionViewModel`（Transient + 内部状态，须局部解析 + 串行）。
3. 禁止绕过 `OutputCategories`/`TemplateFilter` 在业务入口直接 Push Output 却期望变动分类（上下文须在进 Production 前写好）。
4. 禁止另建简易预览页（已删除 GraceDocumentPreview*）；统一 ArchiveOutputPage。
5. `PrintNavigationData` 离开输出流程必须 `Clear()`（PII，含 Prefilter/OutputCategories）。
6. 禁止分页列表失败静默（LoadPageAsync 已改显式失败）。

---

## 7. 冒烟清单

1. 渐退保存 → 提醒 → 进制作页 →「档案输出」→ 模板=变动分类集、预勾：告知书+渐退审批（+减发时保障金减少+有人员变动时增减员表）→ 预览/打印；**无完成归档被误用风险**（文档模式 Hide）。
2. 成员变更/户主变更三选一三路行为正确。
3. 经济复核无渐退→整档；有渐退/减发→输出文书上下文。
4. 渐退期管理页：计数=名单行数、状态/时长正确、失败弹窗不静默。
5. 补打：批量指定模板下拉含 4 张变动文书；按人整档列表挂分类后可见。
6. 变动文书清单含入户调查表且已勾选：补打中心低收入域选人（如卢永华 RuralLowIncome）→ 输出分类「变动文书」→ 出 `档案_入户调查表`，预览字段有值；特困档案出 `档案_特困入户调查表_特困人员`；变更流程「仅出文书」同样出现且恒勾；整档路径列表不变（不重复追加）。
7. `dotnet build` 0 错 0 警。
