# 档案照片 WebP 存储与体积保障（2026-10-24）

## 1. 目标

- 新采集的档案照片统一以 **WebP** 存入 `nc_biz_archive_photos.photo_data`（仍为 `bytea`，不出内网）。
- 单张照片压缩后 **硬上限 500KB**，超过则拒绝入库，不允许退回存原图。
- 历史 JPEG 照片通过「档案照片查询」页的批量转换入口统一转为 WebP。
- 预览、导出、打印保持兼容：库内 WebP 不改变外部使用习惯（打印/预览按需转 JPEG/PNG；导出保持 WebP）。

## 2. 压缩规则

阈值集中在 `Constants/PhotoCompressionConstants.cs`：

| 参数 | 值 | 说明 |
|---|---|---|
| 长边上限 | 2000px | 等比缩放，不放大 |
| 起始质量 | q80 | WebP 有损 |
| 最低质量 | q50 | 低于此值不再降质量，改为缩尺寸 |
| 最低长边 | 1200px | 避免证件文字不可读 |
| 目标体积 | 350KB | 通常压到此值以内 |
| **硬上限** | **500KB（512,000B）** | 超过则压缩失败，拒绝入库 |

算法（`Helpers/ImageCompressor.cs`）：

1. SkiaSharp 解码；失败时用 MAUI `PlatformImage` 兜底（兼容 HEIC/HEIF）转 PNG 再解码。
2. `SKImage.FromEncodedData` 解码时应用 EXIF 方向，避免手机竖拍存成横图。
3. 长边缩到 ≤2000px。
4. WebP q80 → q70 → q60 → q50。
5. 仍超 500KB：长边按 85% 递减（2000→1700→1445→1228→1200），重新按 q80→q50 编码。
6. 仍超限：返回失败，提示重新拍摄；**绝不返回原图**。

已经是 WebP 且 ≤500KB 的字节直接透传，不重复编码。

## 3. 存储与写入收口

- `ArchivePhotoService.SavePhotoAsync` 是唯一写入入口：
  - ViewModel 传原始字节；
  - Service 后台线程压缩为 WebP；
  - 校验 WebP 魔数 + 500KB 硬上限；
  - 写入 `photo_data / file_size / image_format='webp'`。
- `nc_biz_archive_photos` 新增 `image_format varchar(16) NOT NULL DEFAULT 'jpeg'`：
  - 新数据：`webp`；
  - 旧数据：`jpeg`（批量转换后变 `webp`）。
- 迁移脚本：`docs/migrations/20261024_archive_photos_webp.sql`
  - 新增列；
  - `ck_archive_photos_max_size`（`octet_length(photo_data) <= 512000`，`NOT VALID`，新写入立即受约束）；
  - `ck_archive_photos_image_format`（`webp/jpeg/png`）。
- Schema 同步：`Resources/Schema/archive_photos/database.yaml`。

## 4. 历史照片批量转换

入口：桌面端「档案照片查询」页 → `历史照片转 WebP（剩余 N 张）`。

- 服务：`ArchivePhotoWebPMigrationService`（`IArchivePhotoWebPMigrationService`）。
- 游标分批：`WHERE image_format <> 'webp' AND id > $1 ORDER BY id LIMIT 20`，避免 offset 抖动与死循环。
- 每张：
  - 已是 WebP 且 ≤500KB：只补 `image_format/file_size`，计入“跳过”；
  - JPEG/PNG：走同一压缩器转 WebP，更新 `photo_data/file_size/image_format`；
  - 失败：保留原格式，记录日志并计入失败，下次可重跑。
- 支持取消；已完成的记录保留，重复执行自动跳过。
- 转换前提示备份数据库；转换后建议：
  ```sql
  ALTER TABLE nc_biz_archive_photos VALIDATE CONSTRAINT ck_archive_photos_max_size;
  ALTER TABLE nc_biz_archive_photos VALIDATE CONSTRAINT ck_archive_photos_image_format;
  VACUUM (ANALYZE) nc_biz_archive_photos;
  ```
  `bytea` 更新会产生旧元组，磁盘紧张时可在维护窗口执行 `VACUUM FULL`。

## 5. 预览 / 导出 / 打印兼容

新增 `Helpers/ImageTranscoder.cs`（魔数识别 + 按需转码）：

- **桌面预览**：WebP 先转 JPEG 再交给 WinUI，避免 Windows 对 WebP 支持不一致。
- **导出到输出根**：保持 WebP 原格式，文件名扩展名按 `image_format`/魔数取 `.webp`（旧数据 `.jpg/.png`）。
- **导出到系统相册**：`IAlbumExportService` 增加 MIME 参数；Android MediaStore 用 `image/webp`，Windows 写 `.webp`。
- **照片打印**：`PhotoPrintService` 入参 WebP/JPEG/PNG，内部转 JPEG 后插入 Word（Word/WPS 兼容性最稳）。
- **Word 模板照片占位符**：`WordEngine.ReplaceImageFields` 按实际格式写临时文件（WebP→JPEG，JPEG/PNG 透传）。
- 旧 JPEG 照片全部走透传，不重复编码。

## 6. 依赖

- 新增 Windows 平台 `SkiaSharp` 3.119.2 引用（Android 已引用）。
- Windows 输出本来已带 `libSkiaSharp.dll`（NPOI/SkiaSharp 原生资产），本次只补托管 `SkiaSharp.dll`（约 490KB）。
- Android 直接使用现有 SkiaSharp，无需新增原生包。

## 7. 部署顺序

1. 备份数据库。
2. 执行 `docs/migrations/20261024_archive_photos_webp.sql`。
3. 部署新版本（新上传自动 WebP）。
4. 进入「档案照片查询」页，执行「历史照片转 WebP」，观察失败数量。
5. 无失败后 `VALIDATE CONSTRAINT` + `VACUUM (ANALYZE)`。
6. 抽查：桌面预览、导出 `.webp`、Word/WPS 打印、旧 JPEG 记录兼容。

## 8. 验证 SQL

```sql
-- 格式分布/体积
SELECT image_format, count(*) AS cnt,
       max(file_size) AS max_size,
       avg(file_size)::bigint AS avg_size
FROM nc_biz_archive_photos
GROUP BY image_format;

-- 超硬上限（应为 0）
SELECT count(*) FROM nc_biz_archive_photos WHERE octet_length(photo_data) > 512000;

-- 元数据与真实字节数不一致（应为 0）
SELECT count(*) FROM nc_biz_archive_photos WHERE file_size <> octet_length(photo_data);
```

## 9. 回滚

- 代码回滚到旧版本即可继续读取 JPEG/PNG；`image_format` 列可保留（旧代码不读该列）。
- 批量转换不可自动回滚，必须依赖转换前的数据库备份恢复。
- 已转换的 WebP 记录旧代码也能读取（旧 `ArchivePhotoService` 不校验格式），但旧版预览/打印可能无法处理 WebP，因此回滚需同时恢复备份。

## 10. 风险与注意

- 导出保持 `.webp`，Windows 旧看图软件可能打不开；应用内预览和打印已转码，不受影响。若需外发兼容，可后续增加“导出为 JPEG”选项。
- 批量转换会更新 `photo_data`，产生数据库膨胀；转换前必须备份，完成后 `VACUUM`。
- HEIC/HEIF 依赖平台解码器；平台不支持时上传失败并提示，不会存原图。
- 压缩失败的照片保留原格式，不会被删除；页面会显示剩余数量，可修复后重跑。
