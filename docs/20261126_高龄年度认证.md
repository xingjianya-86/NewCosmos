# 高龄年度身份认证（第一至第四批）

> 2026-11-26 新增。范围：批次、应认证名单快照、Excel+图片 ZIP 批量导入、认证结果与凭证查看、
> 停发预览与逐人停发回写、Excel 年度报表、信息变更单与审批。
> Web 端（NewCosmosWeb）已同步同一套 Core/Schema，并实现 Vue 页面与 ASP.NET Core API。
> PDF/打印、移动端专用页面放在后续批次。

## 1. 业务闭环

```
建认证批次（年度/轮次/截止日期）
  → 生成应认证名单快照（在享 Confirmed + 名册 Active 未建档）
  → 腾讯收集表导出 Excel + 图片 ZIP
  → 预览（行匹配、文件名一对一匹配、异常清单）
  → 应用导入（认证结果 + 凭证）
  → 认证名单页查看/手工更正结果/查看凭证
  → 停发预览（待核查/拒绝/不通过/去世/迁出/无法联系）
  → 逐人确认停发 → 回写认证任务 stop_decision=Approved
  → Excel 报表（花名册/汇总/未认证名单）
  → 信息变更单（电话/地址/银行卡/代办人；手工或导入联动生成）→ 审批 → 写入申请主表
  → 后续：PDF/打印
```

认证结果不等于停发决定。认证不通过/拒绝/未核查只形成停发候选，停发仍走现有 `ElderlyApplicationService.StopAsync`。

## 2. 数据表

| 表 | 用途 |
|---|---|
| `nc_biz_elderly_cert_campaigns` | 认证批次：年度、轮次、起止、截止后停发偏移 |
| `nc_biz_elderly_cert_tasks` | 一人一批次一行：名单快照 + 认证结果 + 凭证统计 + 停发决定 |
| `nc_biz_elderly_cert_evidence` | 凭证图片：一人多图按 `seq` 排序；未匹配图片 `task_id` 为空 |
| `nc_biz_elderly_cert_import_batches` | 一次 Excel+ZIP 导入的统计与审计 |
| `nc_biz_elderly_cert_import_rows` | Excel 行暂存：原始值、解析值、匹配结果、错误 |

关键唯一键：

- `tasks (campaign_id, id_card) WHERE deleted_at IS NULL`
- `evidence (task_id, seq) WHERE task_id IS NOT NULL AND deleted_at IS NULL`
- `evidence (task_id, sha256) WHERE task_id IS NOT NULL AND sha256 IS NOT NULL AND deleted_at IS NULL`

Schema 权威定义：`Resources\Schema\elderly_certification\database.yaml`；
存量库迁移：`docs\migrations\20261126_elderly_certification.sql`。

## 3. 认证状态

| key | 含义 |
|---|---|
| `Pending` | 待核查 |
| `Verified` | 已通过 |
| `Refused` | 拒绝核查 |
| `Failed` | 核查不通过 |
| `Deceased` | 已去世 |
| `MovedOut` | 已迁出 |
| `NotLocated` | 无法联系 |
| `Exempt` | 免核查 |
| `Stopped` | 其他原因已停发 |
| `Invalid` | 数据无效 |

认证方式：`Face` 人脸识别、`Onsite` 上门、`Video` 视频、`Photo` 照片、`Other` 其他。

## 4. Excel+ZIP 导入规则

1. Excel 表头需含“姓名”“身份证号”；图片文件名列支持 `图片1/图片2/...` 或 `图片文件名`（分号/顿号/换行分隔）。
2. ZIP 内按文件名一对一精确匹配；规范化大小写、全半角、`\`/`/`、URL 解码、Unicode NFC。
3. 不做模糊自动匹配：同名多文件标“歧义”，找不到标“缺失”。
4. 一人多图按 Excel 列顺序/分隔顺序生成 `seq`；状态分 `Complete/Partial/Missing/Ambiguous/None`。
5. 同一身份证多次提交：优先保留有效行，合并其余行图片，并标记“重复提交”。
6. 名单外身份证只进异常清单，不自动建档。
7. 姓名不一致：按身份证匹配并提示，不自动改名。
8. 已通过/免核查的人出现不通过/去世等不利结果：预览标“结果冲突”，默认不应用；勾选“允许覆盖”后应用（已停发/已去世仍不允许批量复活）。
9. 导入前校验 Excel/ZIP 哈希，预览后文件变化则拒绝应用。
10. 对不上人的图片写入 `evidence.task_id = NULL`，保留在“未匹配图片”池。
11. 导入联动信息变更：Excel 可带 `联系电话/现居住地址/社保卡开户行/社保卡账号/代办人姓名/代办人关系/代领人姓名/代领人关系/代领人开户行/代领人账号`。应用成功后与申请主表当前值比对，**只对已应用且非不利结果的行走**生成 `Pending` 变更单（来源 `CertificationImport`，记录 Excel 文件名与行号）；值未变跳过，申请主表缺失/未确认、银行卡号无法识别（科学计数法/非 12–30 位数字）等记为失败并写入批次摘要，不回滚导入。
12. 导入不直接改电话/地址/银行卡；变更单必须在“信息变更审批”逐笔通过后才写申请主表。

## 6. PDF/打印报表

- 渲染器：`Services\Domain\ElderlyBenefits\ElderlyCertificationPdfRenderer.cs`（桌面与 Web Core 共用）。
- 直接使用 PDFsharp 排版，不走 Office COM：A4 横向、每页重复标题与表头、自动换行/分页、页脚页码。
- 单元格格式与 Excel 一致：整数千分位、金额两位小数、日期 `yyyy-MM-dd`、认证率一位小数。
- 单份报表生成一个 PDF；桌面“打印”会把勾选的多份报表合并成一份 PDF（每份新起一页）。
- 中文字体：`Helpers\ChinesePdfFontResolver.cs` 依次查找 `NC_PDF_FONT_PATH` → Windows 系统黑体/仿宋/楷体 → 应用目录 `Resources\Fonts\notosansregular.ttf` → Linux 常见单文件字体；找不到字体显式失败，不输出乱码。
- Web Server 内置 `notosansregular.ttf` 并随输出/发布复制，Linux 容器不必额外装 `fonts-noto-cjk`；也可用 `NC_PDF_FONT_PATH` 覆盖。
- 桌面打印：优先调用系统 PDF 关联的 `print` 动词；未注册（Win32 1155）时打开默认阅读器由人工打印。
- Web 打印：前端在新窗口打开 PDF Blob，使用浏览器内置 PDF 查看器打印。

## 8. 冒烟验证路径

1. 进入高龄津贴发放 → 年度身份认证 → 新建本年度批次。
2. 点“生成名单”，确认新增人数与在享/名册口径一致。
3. 准备一份 Excel（姓名、身份证号、认证结果、图片1/图片2）和 ZIP（文件名与 Excel 一致）。
4. 预览：检查匹配/名单外/重复/姓名不一致/凭证缺失统计。
5. 应用导入：检查名单行状态、凭证显示、统计卡。
6. 重新导入同一文件：确认不重复插入凭证、结果幂等。
7. 手工“改结果”：检查状态/日期/备注更新。
8. 停发预览：确认待核查/拒绝/不通过/去世/迁出/无法联系进入列表；逐人办理停发，检查任务回写为已停发/Stopped，名单退出预览。
9. 名册未建档人员：确认停发按钮禁用并提示先补建档。
10. 报表：导出 ROSTER/SUMMARY/UNVERIFIED 的 Excel 与 PDF，核对列、合计、认证率、未认证筛选、中文与分页。
11. PDF 打印：勾选多张报表 → 打印 PDF，确认合并为一份、每份新起一页、页码连续；无 PDF 打印关联时应打开阅读器。
12. 信息变更：任务行发起一笔银行/电话变更 → 审批通过 → 检查 `nc_biz_elderly_applications` 已更新、变更单 Approved、历史变更可查；再试旧值冲突应失败。
13. Web：`dotnet build NewCosmosWeb.slnx` + `cd web; npm run build`；登录后走批次/导入/停发/报表（Excel/PDF/打印）/变更审批同路径。
14. 重启应用：确认 Schema 自动建表、页面数据仍在。
