# 临时救助申请日期：未来日期与改期重号（2026-11-25）

> 依据：用户 2026-11-25 口径确认。
> 权威实现：`Constants/TempReliefConstants.cs`（上限/编号）、`Services/Domain/TempRelief/TempReliefService.cs`（改期重号）、
> `ViewModels/TempRelief/TempReliefFormViewModel(.LoadSave).cs`（表单交互）、两个表单页 XAML。

## 1. 规则

| 项 | 口径 |
|---|---|
| 未来上限 | **今天 + 1 个月（含当日）**；`TempReliefConstants.ApplyDateFutureMonths = 1` |
| 过去日期 | 不设下限，保持历史行为 |
| 新建 | 可直接选日期；保存时 LZ 编号按**所选申请日期**生成（不再固定保存当天） |
| 已入库 · 草稿/退回补正 | 日期只读，点「修改」走改期重号流程 |
| 已入库 · 已提交/已确认/已终止/不予救助 | 日期只读，不可改 |
| 改期即时生效 | 点「修改」确认后立即持久化，不依赖表单后续保存 |

## 2. 改期重号（服务端单事务）

`ITempReliefService.ChangeApplyDateAsync(id, newDate, operator)`：

1. 状态闸：仅 `Draft` / `Returned`；
2. 范围闸：`newDate <= 今天 + 1 个月`；
3. 年度唯一：按新日期的 `apply_year` 重跑“每年一次”，排除自身；
4. 重取编号：`LZ{yyyyMMdd}{MAX+1:D4}`，同日序号排除自身；`application_no` 唯一索引兜底并发撞号；
5. 同步字段：`application_no`、`apply_date`、`apply_year`、`accepted_at`、`publicize_start_date`、`publicize_end_date`、`updated_at/by`；
6. 小额快救：免公示，公示起止清空；
7. `created_at` **不改写**（临时救助不以创建时间作档案锚点）；
8. 业务审计：记录旧号、新号、新日期。

并发守卫：`WHERE id = $ AND application_no = $oldNo`；影响 0 行返回“正在被其他操作修改”。

## 3. 表单交互

- 新建（`IsCreateMode`）：`DatePicker` + `MaximumDate = 今天 + 1 个月`；
- 已入库（`IsExistingRecord`）：只读日期框 + 「修改」按钮；
- 「修改」按钮仅 `CanChangeApplyDate`（编辑态 + 草稿/退回补正）可见；
- 改期成功后本地回写 `ApplyDate`、重算公示/验收/批次提示，SnackBar 显示新编号；
- 草稿读入保留已存申请日期，不再强制重置为今天。

## 4. 影响

- 新建单的 LZ 编号日期段改为跟随申请日期；存量编号不回填、不重编。
- 未来日期会把 5/15 日办理时限、公示/验收整体后移；月报归入未来月份。
- 未来单的入户调查打印日期会被钳在 `[申请日, 公示起]`，会打印未来日期。
- 改期不重载表单，未保存的其他编辑不丢失。

## 5. 验证

- `TempReliefConstantsTests`：上限边界（+1 月当天通过、次日拒绝）、编号格式。
- `TempReliefCurveTests`：未来日期曲线（如 2026-12-01 → 公示 12-02~12-04、验收 12-05）。
- 冒烟：
  1. 新建选 12/25（今天 11/25）→ 保留；选 12/26 → 被上限拦截；
  2. 保存 → 编号 `LZ20261225...`；
  3. 草稿改期 12/01 → 确认 → 日期、编号、公示/验收、时限同步；列表显示新编号；
  4. 已提交/已确认 → 无「修改」按钮，服务端也拒绝；
  5. 改到已有申请的年度 → 年度唯一拦截；
  6. 小额快救改期 → 公示起止为空；
  7. 草稿存未来日期后重开 → 日期保留。

无数据库迁移。
